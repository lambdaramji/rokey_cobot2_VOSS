# voss_bringup — 김학민 (@rokeyhak) + 남현지 (@lambdaramji)
launch 파일과 파라미터 (T22 #31). 실행은 사람이 한다 — ros2 launch 는 Claude 가 실행하지 않는다.
- `voss_host.launch.py`: 호스트 전체(런북 T2~T8 + 음성 3노드 + hmi_bridge). **기본 dry_run:=true**(가짜 로봇·RG2), **dry_run 은 도메인 30 이면 기동 거부**(가짜 gateway pose·move_to_zone 이 운용 노드와 섞이지 않게). `dry_run:=false` 는 실기 — T1 두산 브링업(외부 패키지·컨트롤러 IP, 공개 레포에 안 적음)과 **T2 robot_gateway 를 학민이 먼저 따로** 띄워 No-Go 줄을 본 뒤, 비상정지 옆에서. gateway 는 `with_gateway:=auto` = dry_run 일 때만 이 launch 에 들어간다. camera·logger·voice·hmi 는 `auto` = 실기일 때만. 비전은 기본 컨테이너(`docker/vision`), 호스트로는 `with_vision:=true`.
- `voss_vision.launch.py`: box_tracker + label_reader 묶음(컨테이너를 못 쓸 때 호스트 대체, voss_host·voss_dry_run 이 부름).
- `voss_dry_run.launch.py`: 로봇 없이 소프트웨어 전체 루프 — 녹화 재생(`playback_restamp`) → OCR → sort_manager → TrackAndGrasp → gateway dry_run(가짜 PLACE). g0_mock `--log` 로 LOG 준비. TrackAndGrasp 는 기본 `servo:=mock`(g0_mock `--servo`) — 고정 카메라 녹화로는 진짜 belt_servo 가 박스를 화면에 붙잡지 못해 LOST(10/11), `servo:=sim` 은 진짜 belt_servo(sim 파라미터)로 PREPARE·TRACK 확인. **도메인 30 이면 기동 거부.**
- 기동 순서(런북 g0-runbook 2절): 두산 브링업(T1) → robot_gateway(T2, `pose_source:=joint_states`) → 카메라(T3) → sort_logger(T4, sort_manager 보다 먼저) → 비전(T5·T6) → belt_servo(T7) → sort_manager(T8) → 음성 3노드 → hmi_bridge. 운전 시작은 sort_manager 준비 판단(ROBOT·SERVO·VISION·OCR·LOG)이 막는다.
- 끄는 순서: belt_servo 를 gateway 보다 먼저(끊기면 watchdog 이 정지) — 런북 7장. 실기는 Ctrl+C 전에 `/voss/sort/command stop` → PAUSED·로봇 OBSERVE 정지 확인 → 벨트 12 V 끄기. gateway 가 따로 떠 있어 voss_host 를 내려도 gateway 는 남는다.
- 카메라 노출·화이트밸런스 고정값은 `voss_host.launch.py` `CAMERA_PARAMS`(런북 T3 10/08 확인 명령). TCP 등록은 스크립트 없이 gateway 가 `tcp_offset_mm` 으로 변환하고 기동 때 컨트롤러 등록과 같은지 확인한다(#121, 학민).
- 순수 함수(`host_plan`·`gateway_on`·`refuse_dry_run_on_operating_domain`·`dry_run_host_args`·`refuse_operating_domain`)와 "넘기는 인자가 대상 launch 에 선언돼 있는지"는 `test/test_launch.py`.
