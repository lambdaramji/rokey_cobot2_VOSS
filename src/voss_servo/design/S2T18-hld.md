## 0. 먼저 알아 둘 것 — 개념 5개

### 0.1 yaw 와 "180° 대칭"
```
위에서 본 박스 (→ = 베이스 +X)          yaw = 46 mm 긴 변이 +X 와 이루는 각 (반시계 +)
   ┌──────────┐                          ┌──────────┐ 이 박스를 180° 돌려도
   │  송장    │  yaw 0°                  │  송장    │ 그리퍼 입장에선 똑같다 (46 mm 긴 옆면 두 개)
   └──────────┘                          └──────────┘ → yaw 는 (−90°, +90°] 만 쓴다 ("접기")
```
+89° 와 −89° 는 숫자로는 178° 차이지만 실제로는 2° 차이다. 그래서 각을 그냥 평균하면 안 된다.

### 0.2 2θ 공간 중앙값 — 180° 대칭인 각의 "가운데"
```
각을 두 배로 늘리면 +89°→178°, −89°→−178° → 원 위에서 바로 옆 점이 된다.
  1) 각 θᵢ 를 2θᵢ 로 바꿔 원 위의 점 (cos 2θᵢ, sin 2θᵢ) 로 놓는다
  2) x 들의 중앙값, y 들의 중앙값으로 점 하나를 만든다 (튀는 프레임에 강하다)
  3) 그 점의 각을 다시 반으로 → 목표 각
```
흩어짐은 같은 점들의 "평균 길이" R̄ 로 잰다(1 이면 모두 같은 각, 0 에 가까우면 제각각. R̄ 0.97 ≈ 흩어짐 7°).

### 0.3 상대각과 최단 회전
지금 자세(J6 고정, 관측 자세의 공구 yaw ψ_home)는 **박스 긴 변이 벨트 방향과 나란할 때** 31 mm 폭 파지(46 mm 긴 옆면, ADR-0009)가 된다. 박스가 90° 가까이 돌아 있으면 46 mm 폭 파지(짧은 옆면)가 되어 보고 폭이 상한(44.0)을 넘는다(WIDTH_OUT). 그러니 돌릴 양은 박스 yaw 가 아니라 **벨트 방향 기준 상대각** Δ = 접기(yaw_box − yaw_belt) 이고, 목표 공구 yaw 는 **절대값 ψ_target = ψ_home + Δ** 다. 접기 덕분에 |Δ| ≤ 90° 이고, 그 부호 그대로 도는 것이 가장 짧은 길이다.

### 0.4 데드밴드
```
|Δ| < 데드밴드 → 안 돌린다.   예) 송장이 2° 비뚤게 붙어 있고 측정 잡음이 1.3° 면
                              작은 각은 "진짜 기울기"인지 "잡음·붙임 공차"인지 모른다.
```
그리퍼는 닫히면서 작은 각을 스스로 맞춘다(정지 30° 5/5, measurements-1008 #14). 그래서 작은 각은 돌리지 않는 게 낫다.

### 0.5 쿼터니언 → 공구 yaw
`/voss/robot/pose` 의 자세는 쿼터니언 (x, y, z, w) 이다. 회전 행렬의 첫 열 = 공구 x 축 방향이고, 그 XY 각 `atan2(r10, r00)` 이 "공구 yaw" 다. 공구가 아래를 볼 때만 의미가 있으므로 공구 z 축이 연직에서 얼마나 기울었는지도 같이 본다(관측 자세 0.93° *(계산)*).

**D1-3 목표는 절대값, 시작 자세 확인 (r2)**: ψ_target = ψ_home + Δ. ψ_home = 관측 자세의 공구 yaw(파라미터 `rotate.home_tool_yaw_deg`, 제안 −88.72 = observe_pose ZYZ 에서 계산). goal 시작 때 공구 yaw 가 ψ_home ± start_tol(3°) 밖이면 회전하지 않는다(`START_ROTATED`) — 지금 운용(성공 뒤 PLACE 가 OBSERVE 복귀, 실패 뒤 resume 이 OBSERVE 이동, sort_fsm.py:735)에서는 생기지 않지만, 돌아간 채 시작하면 Δ 가 그만큼 틀리기 때문이다.

**D1-4 판정 (모두 제안값, 값은 yaw 관측 실험·측정 ② 뒤 확정)**
| 판정 | 조건 | 행동 | rot_cause |
|---|---|---|---|
| 돌림 | n ≥ n_min(5) · R̄ ≥ R_min(0.97) · min_deg < \|Δ\| ≤ max_deg · 박스가 TCP 상류 | 회전 | — |
| 안 돌림 | \|Δ\| ≤ max(데드밴드 4°, min_deg) | 지금 방식 | `SMALL` |
| 범위 밖 | \|Δ\| > max_deg | 지금 방식 (D8) | `OUT_OF_RANGE` |
| 하류 박스 (r2) | 결정 때 박스가 이미 TCP 하류(벨트 방향 간격 > 0, 늦은 OCR 같은 경우) | 지금 방식 — 이 경우 시야 모델이 비관적이라 판정 근거가 없다 | `DOWNSTREAM` |
| 폴백 | goal 뒤 decide_max_s(0.5 s) 안에 n < n_min, R̄ < R_min, yaw 필드 없음, 시작 자세 벗어남 | 지금 방식 | `NO_YAW`·`SPREAD`·`NO_FIELD`·`START_ROTATED` |
- 단계 적용: 1단계 min_deg 10°·max_deg 45° → 확인 뒤 min_deg = 데드밴드, max_deg 90°.
- Δ 가 정확히 +90°(접기 경계)면 + 방향.
- ⚠ **실기(#179)**: 판정 전에 **flip** — `rotate.flip_above_deg`(70°) 가 있으면 +Δ > 70° 를 Δ − 180°(−110~−90°)로 바꾼 뒤 위 표를 적용한다(+ 회전 67° 이상 시야 LOST 대책, D2-2). max_deg 설계 45(1단계)·90(5단계) → **실기 110 = 180 − flip**(교차 검사 max ≤ 180 − flip·min < flip ≤ 90). 그래서 +90° 경계도 실기에서는 −90° 로 간다.

- 계약상 보정은 gateway 몫(1절) → **r1 의 `rotate.center` 키·보정식은 삭제**. 크기 참고(학민 질문용): 플랜지를 지나는 베이스 Z 축으로 돌면 TCP 반지름 = tcp_offset xy 3.02 mm + 공구 기울기 0.93° × 246.6 mm = 4.0 mm 성분 → **약 6.2 mm** *(계산, 재검 r1)*, 45° 에서 TCP 4.7 mm·90° 에서 8.8 mm 이동.

### D10 J6 부호
- ⚠ **확인됨**: 실기 R1 `angular.z` + → 공구 yaw +(베이스 Z +). J6 관절 부호(설계 −)는 따로 기록하지 않았다(belt_servo 는 쓰지 않는다).
관측 자세 ZYZ(85.25, −179.07, −6.03) 에서 rz +5° → 공구 x 축 yaw −88.72° → −93.72° *(계산, 세션·재검 각각 재현)* → **J6 + = 베이스 Z −**. belt_servo 는 베이스 Z 각속도만 낸다. 관절 부호 변환은 gateway·컨트롤러 몫(학민 질문 ①).

### D11 cutoff 30 — 회전 뒤에도 충분한가
회전이 끝나면(공구 = 박스 각) 카메라와 송장의 상대 기하가 0° 박스와 **같다** — 최종 상태가 "TCP 가 박스 위로 다시 정렬 + 공구 yaw" 로 정해지므로 회전 경로·중심과 무관하다(재검 확인, 축 차이 효과 ≤ 약 1 mm). 하강 중 송장이 화면을 벗어나는 TCP 높이 *(계산, 모델은 실측보다 0~5 mm 보수적)*:
| Δ | 정중앙 | 현장 정렬(along −3) | 극단(along +3·cross +5) |
|---|---|---|---|
| 0° (지금) | 37.0 | 29.0 | 45.5 |
| 30° | 37.0 | 30.5 | 51.0 |
| 45° | 37.0 | 32.0 | 52.5 |
| 90° | 37.0 | 37.5 | 50.0 |
- 결론: **cutoff 30 유지**. 극단 정렬 오차 민감도는 지금도 있고 각도에 따라 최대 +7 mm. 회전하지 않은 기울어진 박스의 이탈 높이는 15/30/45/60° 에서 42.5/45.5/44.5/39.5(접근 +40 보다 높음) — 10/12 DESCEND LOST 와 같은 방향이고, J6 가 이 문제를 없앤다.
