**후퇴 상한이 걸리는 구간 (코드로 확정)**:
- `fsm.py:202-208` `lift_since_next` — `phase != LIFT or state.hold_z` 이면 None. 개방을 기다리는 동안(hold_z)은 **상승 시계가 돌지 않는다**.

**RISING(2.27~2.30)이 정상 LIFT(2.70~2.77)보다 0.45 s 빠른 이유** (틱 `cmd_vel_mps`): 가속 제한은 xy·z 를 합친 **벡터** 예산이다(0.1 m/s²). 정상 LIFT 는 시작하자마자 xy 를 FF→0 으로 감속하느라 예산을 나눠 써서 z 램프가 느리다. 후퇴는 핑거 끝이 윗면 +10 을 넘을 때까지 xy FF 를 **유지**(속도 변화 없음)하므로 z 가 예산을 다 쓴다. 그 뒤 xy 감속이 z 감속과 예산을 나눠 z 가 P 계획보다 오래 빠르게 남는다. (A1 정상 LIFT vs C1 RISING, 각 구간 첫 틱 기준: 0.6 s 에 z 명령 54 vs 63 mm/s, 1.0 s 에 44(= P) vs 53(P 38) — 기준 시각에 따라 ±3 mm/s.) 예측식 2.785 s(`lift_max_s` 의 정지 출발 계산)는 둘 다보다 길어 상한은 보수적이다.

**개방 응답 1.13~1.20 s vs 사전 개방 0.17~0.20 s (독립 가설)**: H1 "핑거가 실제로 움직이느냐" / H1' "열 거리에 비례" / H2 "박스를 쥔 상태라 느림" / H3 "세션 첫 동작". 대조: 세션 첫 사전 개방 A1 은 **쥔 것 없이** 51.2 → 90.4 mm 에 1207 ms, 후퇴 개방 55.5~55.9 → 90.2~90.4(34~35 mm)는 1116~1181 ms, 10/12 16:37 로컬 세션의 사전 개방 41 → 90 mm(49 mm)는 1184~1220 ms, 평소 사전 개방(이미 90 mm, PLACE 에서 열림)은 165~180 ms. → 거리 34~49 mm 에 시간이 거의 같다(1.12~1.22 s) — **H1' 기각**(재검 지적: 처음 적은 "28 mm/s 비례" 는 산술 오류였다), **H1 생존**: 움직이면 ≈ 1.1~1.25 s, 안 움직이면 0.17~0.20 s. H2 반박(빈손 A1 도 1.21 s), H3 은 H1 의 경우. 정상 파지 뒤 개방도 ≈ 1.2 s(실측) — 2.5 상한(실기 당시 2.3) 안.

**바꾸면 필요한 것**: ① 레포 `config/voss_config.yaml` `belt.speed_cmps` 4.8 → 4.73 PR(오너 남현지·학민, `interface` 라벨 여부는 docs/interfaces 의 값 기재 여부로) ② config_sha `9aad3af065d5`·params `1a28b8c912f0` = 새 고정 조건 ③ **ADR-0002:32 "h250 반듯한 박스 10회 이상 다시 재고"** → s3 5 + 추가 5. 4.8 을 유지해도 s2 반듯한 박스는 A 6회뿐 → 추가 4회. **어느 쪽이든 T29 회귀가 필요**하다. 0 실패 n 회의 성공률 단측 95 % 하한 = 0.05^(1/n): n 5 → 55 %, n 10 → **74 %**, n 14 → 81 %.

### ⑧ 정지 4.73 vs 추종 중 4.68~4.70 — 가설 → 대조 → 반박 → 결론 (Fable C 독립 분석 → 세션 재검)

용어: **직선 맞춤 기울기** = 시간-위치 점들을 가장 잘 지나는 직선의 경사(= 속도). **핸드아이 스케일** = 픽셀 1칸이 몇 mm 인지(카메라–윗면 거리로 정해짐). 정지 카메라에선 박스가 화면을 가로질러 흘러 스케일 오차가 속도에 그대로 묻고, 박스를 따라가는 카메라에선 박스가 화면에 거의 고정이라 묻지 않는다.

**결론**: 같은 추정 공식이 카메라 상태만 다르게 낸 두 값이다. 차이 ≈ 1.0~1.2 % 는 box_tracker 좌표의 스케일(+롤링셔터 일부) 편향. 진짜 벨트 속도는 **4.68 쪽**.
**뜻**: ① FF 를 4.73 으로 해도 4.68 대비 0.5 mm/s × 약 4 s ≈ 2 mm — ⑦ 결론 그대로. ② "2 % 이상이면 추정 FF" 단계를 쓰려면 비교 기준(정지 실측)이 같은 편향을 가지므로 기준을 먼저 정의하고, 맞춤 창을 TRACK 등높이·가속 뒤로 제한해야 한다(후속, 시연 뒤). ③ 근본 수정은 box_tracker 스케일 재보정(남현지).
**실험 제안(🤖, 시연 뒤)**: 벨트 정지·박스 고정, 로봇 4.8 cm/s 등속 통과 → 박스 좌표가 흐르는 방향으로 스케일(−0.6 mm/s)과 롤링셔터(+0.4 mm/s)를 가른다.

## 10. 처음 보는 개념 (한 줄씩)
- **틱 양자화**: 33 ms 마다 한 번만 보니, 문턱을 "지난 첫 틱"의 값은 한 틱 이동량(1.6 mm) 범위 안 어디든 된다.
- **반사실 재생**: 실제 로그 시각을 그대로 두고 "그때 값이 달랐다면" 을 다시 계산해 보는 것(여기선 cutoff 10 vs 30).
- **정상상태 오차**: FF 가 실제보다 빠르면 P 가 늘 조금 뒤로 당겨야 해서 생기는 고정 어긋남 = 속도 차 ÷ Kp.
- **핸드아이 스케일 편향**: 픽셀→mm 비율이 1 % 틀리면, 화면을 크게 가로지르는 박스(정지 카메라) 속도에 1 % 가 그대로 묻는다.
- **특이점 영역 안내(3205/3206)**: 두산이 "팔이 다루기 어려운 자세 근처에 들어감/나옴" 을 알려 주는 정보 메시지(오류 아님).
- **단측 95 % 하한 0.05^(1/n)**: n 번 모두 성공했을 때 "성공률이 이 값보다 낮을 가능성은 5 % 이하" 라고 말할 수 있는 값.
