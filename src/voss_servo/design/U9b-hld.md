# U9-b HLD — 재시도 재접근 재설계 + 안전 후퇴 (T28 #37)

근거: FIELD-1010-analysis(U-A) §2·§5 #12·§6.1, docs/measurements-1010 §5·§6, 지시서 U9b-37-retry-reapproach,
U9-c(5604904: x_max 600·close 2.3 → x 여유 문턱 352.9 mm), U9-a HLD(cutoff 30 → 사각 이탈 높이 박스 윗면 +35, 사각 체류 상한 ≈3.1 s).
베이스 5604904. 코드는 U9-a 끝 커밋 위로 리베이스한 뒤 쓴다.

## 0. 한 줄 결론 (제안)

**재정렬형 재시도는 현장 타이밍(정렬 x 85~91 mm)에서 어떤 안으로도 x 600 안에 들어오지 않는다.**
그래서 이번 단위의 중심은 두 가지다:
1. 1차 실패 직후 "재시도할 x 여유가 있나"를 바로 재고, 없으면 **올라가서 재정렬하지 않고** 끝낸다 (c).
2. 끝낼 때 **박스 윗면 위 안전 높이까지 후퇴한 뒤** 결과를 보낸다(새로 찾은 안전 문제, 2절).

여유가 있으면(1차 정렬 x ≤ 약 22 mm) 지금의 재정렬형 재시도를 그대로 쓴다. `retry.max_attempts` 기본값은 1 로 둔다.

## 1. 기하·시간 계산 (독립 계산 2개 일치)

계산 A = 이 세션이 실제 `control.command`(z P 제어·벡터 clamp·FF)를 30 Hz 이상적 로봇에 돌린 시뮬.
계산 B = Fable 서브에이전트가 같은 코드를 따로 읽고 식 + 시뮬로 낸 값. 두 값은 1~3 mm 안에서 같다.
값: 벨트 48 mm/s, kp_z 1.5, 하강 0.05·상승 0.08 m/s, 가속 0.1 m/s², 접근 +40, 들기 +50, 파지 −19, height_tol 2, 사각 이탈 +35.

### 1.1 1차 시도와 현재 재시도의 x (정렬 x_a = 90 기준)

```
 x(mm)  90        215          298            389        419                 600
        │ DESCEND │   GRASP    │  PREPARE(재상승) │ TRACK   │                  │x_max
        ├─2.64 s──┼─1.73 s─────┼── 1.94 s ──────┼─0.6 s───┤                  │
        정렬      파지 높이     1차 실패         사각 이탈   재정렬 → 문턱 352.9 넘음
                                (빈손 판정)      (+35)      → OUT_OF_REACH(REACH_GRASP_ROOM)

 z(윗면 기준 mm)
   +40 ─┐                                         ┌──────── 접근 높이
   +35  │ ·  ·  ·  ·  ·  ·  ·  ·  ·  ·  ·  ·  · ┌┘  ← 사각 이탈(이 위에서 다시 보인다)
        │                                     ╱
     0 ─┼── 박스 윗면 ─────────────────────── ╱ ──────
        └╲                                  ╱    (P 제어 꼬리: 가까울수록 느려짐)
   −19    ╲______________________________╱

```

- 하강 예상 2.64 s(현장 2.60~2.63) + 닫힘 상한 2.3 s → 필요 길이 247.1 mm → **정렬 문턱 x ≤ 352.9**.
- 1차 실패 x: x_f = x_a + 208(닫힘 1.7 s) / 229(2.13) / 237(2.3) → 현장 x_a 85~91 이면 **x_f ≈ 293~328**.
- 재상승: 사각 이탈까지 1.94~1.97 s, ±2 mm 접근 높이 도달까지 2.54~2.57 s. 그리퍼 개방(미측정, 1.0~2.3 s 가정)은 이 시간 안에 숨는다.
- 재상승 중 벨트 방향 처짐 최대 1.5 mm(가속 clamp 가 지배, 속도 clamp 는 거의 안 걸림) — 무시 가능.

### 1.2 "재시도가 가능한 1차 실패 x 상한"

| 재시도 방식 | 실패 → 재정렬 | **x_f 상한** | 1차 정렬 x_a 상한 (닫힘 1.7 / 2.13 / 2.3 s) |
|---|---|---|---|
| 현재(접근 높이까지 재상승) | 2.57 s, +123 mm | **230 mm** | **22 / 1 / −7 mm** |
| (a) 사각 이탈 높이에서 정렬 허용 | 2.07 s, +99 mm | 254 | 46 / 25 / 17 |
| (b) 사각 중 FF+P | 2.57 s | 230 | 22 / 1 / −7 (이득 0) |
| (d) 재시도 전용 사다리꼴 z | ≈1.7 s | ≈272 | 64 / 43 / 35 |
| DROPPED(VERIFY 에서 놓침) | 7.6 s, +363 mm | −176 (x_min 밖) | 불가능 |

- 현장 x_a 85~91 을 덮으려면 재정렬까지 1.4 s 이상 더 줄여야 한다 → 이번 범위(사다리꼴 z 는 2차 과제)로는 불가능.
- **sim_check `retry` 케이스는 x_a ≈ −30 mm 로 만든다**(x_f ≈ 178~207, 상한 230 안 → 2차 GRASP 가 실제로 실행된다).

## 2. 새로 찾은 안전 문제 — 실패로 끝난 자리

지금 코드에서 GRASP_FAILED 로 끝나면(재시도 없음, `max_attempts` 1 = 현장 설정):
- 종료 틱부터 속도 0, 0.5 s 유지 뒤 gateway watchdog move_stop → 로봇은 **파지 높이(핑거 끝 벨트 위 약 8 mm), 그리퍼 닫힌 채** 멈춘다.
- sort_manager 는 실패면 PAUSED, 팔을 움직이지 않는다(`sort_fsm.py:733~738`). 벨트는 계속 돈다.
- → 놓친 박스가 핑거 상류에 있으면 곧바로 걸리고, **다음 박스(높이 27 mm)는 멈춘 핑거에 부딪힌다**. 10/10 은 실패 0회라 이 경로를 한 번도 안 탔다.

필요한 것 = **안전 후퇴**: 결과를 보내기 전에 박스 윗면 위로 올라간다.
- 핑거 끝이 박스 윗면을 넘는 데 약 0.7 s. 그동안 xy 는 FF(박스와 같이 이동, 상대 위치 0) → x +31 mm.
- 그 뒤 xy 0, z 만 들기 높이(+50)까지 → 도달하면 끝. 총 약 2.7 s, x 약 +43 mm.
- 후퇴 중에는 x 끝 검사(OUT_OF_REACH)로 끊지 않는다. 대신 x_max 에 닿으면 xy 를 0 으로(그 자리에서 수직 상승).

## 4. 선택안: (c) + 안전 후퇴 + 재정렬형 재시도 유지

```
GRASP/VERIFY 에서 NOT_HELD
   ├─ VERIFY(DROPPED) ─────────────────────────────► 끝 GRASP_FAILED (이미 들기 높이 = 안전, 재시도 안 함)
   └─ GRASP
        ├─ 시도 남음 && 재시도 x 여유 있음 ────────► PREPARE (지금과 같음: 개방 + 접근 높이로 재상승 → TRACK → 재정렬)
        │      여유 = x_max − x_f ≥ 벨트 × (재상승 예상 + 하강 예상 + 닫힘 상한) + 여유 10
        └─ 아니면 ──────────────────────────────────► 안전 후퇴(LIFT 높이까지, 처음엔 FF·윗면 넘으면 xy 0)
                                                            └ 들기 높이 도달 ─► 끝 GRASP_FAILED
```

- 재시도 x 여유 검사는 `grip.grasp_room_ok` 를 재사용하고, 필요 시간만 "재상승 + 하강 + 닫힘" 으로 늘린다.
  재상승 예상은 `grip.descend_time_s(접근−파지, 상승 속도, …)` ≈ 2.66 s(시뮬 2.57 보다 약간 보수적).
  정렬 순간의 기존 검사(TRACK → DESCEND)는 2차 안전망으로 그대로 둔다.
- 폭 밖(WIDTH_OUT)은 핑거 사이에 무언가 끼어 있다 → **먼저 열고(FF, z 유지) 연 뒤에 올라간다**(끼운 채 들면 높은 데서 떨어뜨린다).
  재시도 경로(PREPARE)도 같은 규칙: 폭 밖이면 개방 응답 전에는 상승하지 않는다(지금 코드는 개방과 상승을 동시에 시작한다 — 고칠 점).
  이때 재시도 여유 계산에 개방 시간(close_time_max 를 대용)이 더해져 사실상 재시도 불가 → 후퇴로 간다.
- 결과·`attempts` 는 지금과 같은 의미(GRASP 진입 수). reason 은 `GRASP_FAILED` 그대로, cause 는 원래 판정(NOT_DETECTED·WIDTH_OUT·DROPPED) 유지.
  재시도 여유 부족으로 포기했는지는 로그 필드로 남긴다(DD 에서 이름).
- 후퇴 중 feedback phase 는 **LIFT** 로 보인다(계약 phase 6종 안 — 새 값은 interface 변경이라 쓰지 않는다). 로그에는 후퇴임을 따로 표시.
- 후퇴 중 취소 → 지금처럼 stop 호출 → CANCELED(그 자리에서 멈춘다, 계약). 후퇴 중 pose 끊김 → STALE_INPUT(제어할 수 없으므로).

## 9. 재검 r1 (독립 Fable 5.1, 10/12) — HLD 에 닿는 변경

상세 처리표는 [U9b-dd.md](U9b-dd.md) 9절. HLD 결론((c) + 안전 후퇴 + 재정렬형 재시도 유지)은 그대로.
- 폭 밖(WIDTH_OUT)은 **항상 후퇴**(먼저 개방). 재시도하려면 실패 x ≤ 115 mm 라 도달 불가 → 4절 "재시도 경로(PREPARE)도 같은 규칙" 분기는 두지 않는다.
- 개방 대기는 2.3 s 또는 x_max 에서 끝내고 올라간다(파지 높이 정지 방지).
- LIFT 체류 상한은 **후퇴에만**. 정상 들기(박스 쥔 채)는 경고 로그만 — 20/20 성공 경로를 현장 자료 없이 바꾸지 않는다.
- sim `retry` 는 kp 3 + 박스 시작 −250 + 닫힘 1.2 s (sim 정렬 x 는 P 추격이 정한다 — 1.2 의 "x_a ≈ −30" 만으로는 안 됨).
