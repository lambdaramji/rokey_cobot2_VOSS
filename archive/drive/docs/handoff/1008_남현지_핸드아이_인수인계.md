# 핸드아이 캘리브레이션 인수인계 — 10/08 오전 (남현지 → 김학민)

> 공용 PC + 로봇, 약 40~60분. 로봇은 김학민 님이 움직이고 남현지가 촬영 도구를 누릅니다. 이 문서만 보고 학민님 혼자서도 끝까지 할 수 있게 썼습니다.
> 도구·계약: PR #90 (`feat/25-vision-hand-eye`), `docs/interfaces/calibration.md` "핸드아이 결과 파일" 절.

## 왜 하나
- G0(10/10)는 **카메라가 움직이는 동안에도** 박스 위치(`BoxTrack.position_base`, `SOURCE_HAND_EYE`)를 요구합니다.
- 지금 있는 T16 호모그래피는 관측 자세에 멈춰 있을 때만 맞습니다.
- 그래서 오늘 **TCP → 카메라 변환(`T_tcp_camera`)** 을 구합니다.
- T16 점만으로는 이 변환이 정해지지 않습니다(PnP 와 호모그래피 분해가 37 mm·7° 차이). 보드 촬영이 꼭 필요합니다.

**원리(Eye-in-Hand)**
- 보드는 책상에 고정하고, 로봇만 여러 자세로 움직이며 찍습니다.
- 사진마다 아는 것이 두 가지입니다.
  - 로봇이 알려 주는 "베이스 → TCP" (`/voss/robot/pose`)
  - 보드 코너로 계산한 "카메라 → 보드"
- 모르는 것은 늘 같은 "TCP → 카메라" 하나뿐이라, 20장 정도면 `cv2.calibrateHandEye`(PARK)로 풀립니다.

## 어제(10/07) 학민님 결과로 확인된 것
- `/voss/robot/pose` 50 Hz, 컨트롤러 TCP 와 0.001 mm 이하, 정지 중 흔들림 0 → 촬영 도구의 "멈춤 확인"(0.5 초 동안 0.2 mm 이하)이 확실히 동작합니다.
- 게이트웨이 쿼터니언과 우리 ZYZ 해석이 0.0001°·0.0005 mm 로 일치합니다(남현지 계산). 그대로 씁니다.
- 촬영 도구는 **두산 서비스를 부르지 않고** `/voss/robot/pose` 만 구독합니다. 게이트웨이는 계속 켜 두세요.

## 3. 카메라 (T3) — 운용 설정 1920×1080·노출 6 ms·WB 4600, 깊이 끔
`realsense` 별칭은 깊이를 켜고 해상도가 다를 수 있어 쓰지 않습니다. 다른 카메라 노드가 떠 있으면 먼저 끕니다.
```bash
ros2 launch realsense2_camera rs_launch.py camera_namespace:='' camera_name:=camera \
  enable_depth:=false rgb_camera.color_profile:=1920,1080,30 rgb_camera.enable_auto_exposure:=false
```
다른 터미널에서 노출·WB 고정 (카메라 파라미터만 바꿈, 로봇과 무관):
```bash
ros2 param set /camera rgb_camera.exposure 60            # 단위 0.1 ms → 6.0 ms (10/06 #9)
ros2 param set /camera rgb_camera.enable_auto_white_balance false
ros2 param set /camera rgb_camera.white_balance 4600
ros2 topic hz /camera/color/image_raw                     # 약 30 Hz
ros2 topic echo --once /camera/color/camera_info | grep -E "^(width|height)"   # 1920 / 1080
ros2 topic hz /voss/robot/pose                            # 약 50 Hz (게이트웨이)
```

## 4. 보드 놓기

## 5. 로봇 움직이는 방법 — 학민님이 정해 주세요
어제 확인하신 대로 펜던트 값은 제어권을 회수하지 않으면 볼 수 없습니다. 자세는 도구가 `/voss/robot/pose` 로 자동 기록하니, 이동 수단만 정하면 됩니다.

| 방법 | 장점 | 주의 |
|---|---|---|
| **직접교시(핸드가이드)** — 강의 42쪽 | 기울기·회전을 빨리 다양하게 만들 수 있음. 손을 떼면 그 자리에 섬 | 모드 전환 명령은 학민님이 실행. 직접교시 중에도 게이트웨이 pose 가 50 Hz 로 나오는지 먼저 `ros2 topic hz` 로 확인. 끝나면 원래 모드로 |
| 펜던트 조그 | 익숙함 | 제어권 회수가 ROS 연결·게이트웨이에 주는 영향 확인 필요 |
| ROS `move_line` ASYNC (어제 조그 시험처럼) | 재현 가능, 속도 고정(20 mm/s) | 회전 목표를 직접 넣어야 함. 관절 한계·충돌을 매번 확인 |

추천은 **직접교시**입니다. 어느 방법이든 **촬영 순간에는 로봇이 완전히 멈춰 있어야** 합니다. 도구가 0.5 초 동안 0.2 mm·0.05° 넘게 움직이면 저장을 거부합니다.

### 자세 계획 (24장 목표, 최소 20장)
핵심은 **각도를 다양하게** 하는 것입니다. 평행이동만 바꾼 자세는 풀이에 도움이 안 됩니다. 공구축 회전은 ±60° 안에서 합니다(그보다 크게 돌리면 일부 풀이법이 흔들리고, 케이블도 위험).

| 묶음 | 카메라~보드 거리 | 공구 기울기 | 기울이는 방향 (8방향) | 공구축 회전 |
|---|---|---|---|---|
| A (1~8) | 약 35 cm | 15° | 앞·뒤·좌·우·앞좌·앞우·뒤좌·뒤우 | 0, +30, −30, +60, −60, +30, −30, 0 |
| B (9~16) | 약 42 cm | 20° | 같은 8방향 | −30, 0, +30, −60, +60, 0, +30, −30 |
| C (17~24) | 약 50 cm | 25° | 같은 8방향 | +60, −30, 0, +30, −60, −30, 0, +60 |

- 도구가 매 장마다 `보드 거리 · 공구 기울기 · 첫 자세와 회전 차` 를 보여 줍니다. 표와 대충 맞으면 됩니다(정확할 필요 없음).
- 보드 전체가 화면 안에 들어와야 저장됩니다. 안 되면 조금 높이거나 덜 기울입니다.

## 6. 촬영 (T4)
```bash
python3 ~/voss_he/tools/calib/handeye_capture.py --out ~/voss_data/1008/handeye
```
- `[HE_01] 로봇이 멈춘 뒤 Enter` → 학민님이 "멈춤" 하면 현지가 Enter.
- `저장 HE_01: 보드 거리 41 cm, 공구 기울기 18°, 첫 자세와 회전 차 0°, 코너 재투영 0.2 px, pose 25개` 같은 줄이 나오면 성공입니다.
- 거부 메시지와 대처:
  - `로봇이 아직 움직인다` → 1초 더 기다렸다가 Enter
  - `보드 코너를 못 찾았다` → 보드 전체가 보이게 자세를 바꾸고, 반사·흔들림 확인
  - `pose N개 — 게이트웨이 확인` → T2·`ros2 topic hz /voss/robot/pose`
  - `새 영상 없음` → T3 확인
- 24장 다 찍으면 `q` + Enter. 중간에 끊겨도 같은 명령을 다시 실행하면 **이어서** 번호가 붙습니다(최대 40장).
- 게이트웨이가 아예 안 되면 `--manual-pose` 를 붙여 펜던트·서비스로 읽은 TCP 값(x y z rx ry rz)을 직접 입력할 수 있습니다(마지막 수단).

## 8. (시간 되면) 이동 중 검증 녹화 — 약 10분
`moving_verified` 를 true 로 만들 데이터입니다. 분석은 남현지가 합니다(멈춘 박스의 위치가 로봇 이동 중 5 mm 안에서 흔들리는지).
1. 벨트는 끈 채로, 송장 붙은 박스 1개를 관측 자세 화면 가운데(벨트 위)에 둡니다. 보드는 치웁니다.
2. 녹화 시작(T4):
   ```bash
   ros2 topic list | grep compressed      # /camera/color/image_raw/compressed 있는지
   ros2 bag record -s mcap -o ~/voss_data/1008/he_moving_01 \
     /camera/color/image_raw/compressed /camera/color/camera_info /voss/robot/pose
   ```
3. 학민님이 관측 자세에서 **저속(20 mm/s)** 으로: z −50 mm → 2초 멈춤 → 원위치 → x +40 mm → 2초 → 원위치 → x −40 mm → 2초 → 원위치. 박스가 화면 안에 계속 있고 핑거가 박스 윗면보다 30 mm 이상 위인지 확인하며 움직입니다(수치는 학민님 판단으로 줄여도 됨).
4. Ctrl-C 로 녹화 끝.
