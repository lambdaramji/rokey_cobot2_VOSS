## #4 핸드아이 상세
- 내부 파라미터: 공장 camera_info 는 d = 0 이라 보드 재투영 1 px 를 못 맞춰, 보드 27장으로 **재추정**(fx 1358.1, fy 1357.5, cx 976.0, cy 551.4, 5계수, rms 0.262 px). 공장 K 는 `camera_factory` 로 남겨 운용 중 camera_info 비교에 쓴다.
- 풀이: PARK, 27장 모두(재투영 최대 1.27 px). 보정 전 위치 [30.31, 73.86, −221.66] mm.
- 보정: 회전 그대로, 카메라 위치만 T16 15점(10/06·07) + 터치 5관측(10/08, P4 −60 mm 포함)에 맞춤 → [−0.73, −0.49, **+9.19**] mm(카메라 좌표) → 위치 **[31.07, 74.40, −212.47] mm**.

| 보정 | T16 15점 최대 / 평균 | 터치 5관측 최대 / 평균 |
|---|---|---|
| 없음 (보드 풀이) | 5.67 / 3.11 | 6.06 / 3.34 |
| 터치만 (광축 +11.0, 옆 −2.0, 학민 안) | **6.53** / 2.86 | 1.07 / 0.79 |

| **T16 + 터치 (채택)** | **4.56 / 2.14** | **2.44 / 1.96** |

- 터치 4점이 화면 한 세로줄(u ≈ 1131–1142)에 있어 터치만의 옆 방향 보정은 그 줄에만 맞았다. 광축 방향은 T16 만으로도 +10.3 mm 가 나와 같은 결론.
- 보정 뒤 보드 흩어짐은 4.09 mm 가 된다 = 보드 데이터와 TCP 좌표 데이터(T16·터치)의 어긋남. 공구가 수직이면 카메라 거리 오차와 평면(터치 z·TCP z) 높이 오차는 효과가 같아 가를 수 없다(자로 잰 "플랜지 면 → 렌즈 면 36 mm" 는 렌즈 앞면이라 광학 중심과 몇 mm 다를 수 있다). 보정은 그리퍼가 가는 TCP 좌표에 맞췄으므로 **수직 공구(G0 고정 파지 자세)에서 유효**. 공구를 기울여 쓰기 전, 또는 이동 중 오차가 5 mm 를 넘으면 기울기 30° 이상 자세로 다시 찍는다.
- 재현: `tools/calib/fit_hand_eye.py --intrinsics board --reproj-max-px 1.3 --touch …` (#90).

## #6 지연이 쓰이는 곳
- `/voss/robot/pose` stamp 의 뜻(게이트웨이 응답 수신 시각, MC-004)은 바꾸지 않는다. box_tracker 가 촬영 시각 + 60 ms 의 pose 를 쓰고, 그 pose 가 아직 없으면 80 ms 까지 앞으로 외삽한다(calibration.md).
- belt_servo 도 같은 pose 를 쓴다. 벨트 속도 48 mm/s 에서 60 ms ≈ 2.9 mm (박병후 공유).
- 시험 속도 20 mm/s 에서 지연 0 최대 4.08 mm 였으므로, 벨트 속도에서 보정 없이 두면 약 5.8 mm 까지 갈 수 있다(추정).
