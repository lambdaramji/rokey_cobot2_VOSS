TCP = voss_config `robot.tcp_offset_mm`(플랜지 → 핑거 끝, #57), robot_gateway 가 브링업마다 등록하고 변환한다 — zones·observe_pose 는 플랜지 그대로(#53 MC-010). stamp = `aux_control/get_current_tool_flange_posx`(플랜지 posx → TCP 변환) **응답 수신 시각**(호스트 시계, 측정 시각 아님). 요청·응답 시각·RTT·큐 대기를 로그로 남기며, 수신 시각이나 RTT/2 를 실제 측정 시각·보장 오차로 쓰지 않는다 — #53 MC-004), `/voss/robot/state` (voss_msgs/RobotState — 필드는 voss_msgs.md RobotState, 상태가 바뀔 때 + 2 Hz, #55 MC-019). 서비스: `/voss/robot/stop` (std_srvs/srv/Trigger: 신규 작업·servo_cmd 를 막고 두산 `move_stop`(Quick stop)을 요청. `success=true` = move_stop 정상 응답, `false` = 응답 없음/오류(`message` = `TIMEOUT`/`DEVICE_ERROR`). 정지 확인·물리 정지 지연의 보장이 아니고 별도 `STOP_UNCONFIRMED` 는 없다 — #53 MC-014. **F-04 제안(#84 리뷰):** stop 은 멱등(이미 정지 중이어도 `success=true`, 남현지), stop 이후 들어온 서비스 요청은 다시 받고 servo_cmd 는 stop 이전 stamp 를 버리고 새 stamp 부터 받는다(김학민)), `/voss/robot/move_to_zone` (srv/MoveToZone), `/voss/robot/gripper` (srv/Gripper), `/voss/robot/teach_zone` (srv/TeachZone). **자원 규칙(#53 MC-013):** 모션(servo_cmd 추종·MoveToZone)과 RG2 는 서로 다른 자원이고 각 자원은 한 번에 하나만 실행한다 — 같은 자원의 두 번째 명령은 거부한다 — 서비스는 `BUSY`, servo_cmd(토픽)는 응답할 수 없으므로 무시하고 로그를 남긴다. MoveToZone PLACE·PICK 은 모션과 RG2 를 함께 점유한다(놓기 개방·집기 닫힘 — 그동안 Gripper 호출도 `BUSY`). stop 은 두 자원 모두에 우선(김학민 #84 리뷰). 스트리밍 목표는 서비스 큐 밖에서 최신 하나만 유지한다. 회전 명령을 쓰면 TCP 선속도가 servo_cmd 값과 맞도록 보정하는 것도 gateway 몫이다(G0 는 각속도 0, #53 MC-010). `servo_cmd` 만료 watchdog 은 200 ms(gateway 파라미터 `servo_watchdog_s`, F-04 10/08 5 mm/s 실측 — ADR-0010. 만료·stop·종료 때 0 속도 + 항상 move_stop, TCP z 하한·추종 구간 x 는 감속 거리를 빼고 자름) | `/voss/robot/servo_cmd`. 두산: `/dsr01/dsr_controller2/motion/move_line` (ASYNC), 스트리밍 `/dsr01/dsr_controller2/servol_stream` (dsr_msgs2/msg/ServolStream)·`/dsr01/dsr_controller2/speedl_stream` (SpeedlStream) — 경로·타입은 실기 브링업에서 **존재만** 확인(10/07, #55). 서보 추종은 `speedl_stream` 을 쓰고 move_line ASYNC 는 쓰지 않는다(박병후 10/07). 실제 스트리밍 적용·주기는 pending #8 실측(T25, PR #87), `aux_control/get_current_tool_flange_posx`. RG2: Modbus TCP 직접 (ADR-0005) |

## QoS 제안
| 토픽 | reliability | durability | depth |
|---|---|---|---|
| /voss/vision/box, /voss/robot/pose, /voss/robot/servo_cmd | best_effort | volatile | 1 |

`/voss/vision/box` 는 **한 프레임의 트랙마다 한 건씩** 연달아 발행한다 → 구독 depth 1 이면 같은 프레임의 앞 트랙이 덮인다. **구독 depth ≥ 동시에 보이는 박스 수(제안 5)**, track_id 별 최신값을 보관한다(발행 depth 는 1 그대로, #95 박병후 리뷰).
