# voss_msgs 필드 정의 (src/voss_msgs 와 1:1 — 둘 다 같이 고친다)

## BoxMotion 확장 제안 (2026-10-13, 구두 승인 전달 · IDL 미반영)

현재 main 의 `src/voss_msgs` IDL에는 아직 반영되지 않았다. 메시지·서비스 타입 해시가
바뀌므로 관련 노드 담당자 승인과 일괄 재빌드 전에는 운영 계약으로 사용하지 않는다.

**BoxMotion ROS 발행 토픽명(제안):** `/voss/hmi/box_motion` (기존 영역 누락을 수정한 이름; 10/14 김학민 PL 대행 확정). MQTT `voss/box_motion`·SSE `box_motion`은 그대로다. 메시지 타입·서비스 IDL 변경은 이 PR에서 하지 않는다.

`BoxMotion.msg`: `string session_id`, `string box_id`, `int32 track_id`, `string phase` (`GRASPED`/`RELEASED`), `builtin_interfaces/Time stamp`, `string zone`. `GRASPED`는 LIFT·VERIFY 완료 후 manager가 `TrackAndGrasp.Result(reason=OK, grasped=true)`를 확인한 시각(물리 그리퍼 닫힘 시각 아님), `RELEASED`는 gateway의 PLACE RG2 개방 성공 `placed_stamp`이다. 이벤트는 실제 로봇 제어에 사용하지 않는다. `MoveToZone.Request` 끝에는 시각화 상관관계용 `session_id`, `box_id`, `track_id`를 추가한다. 자세한 발행·보정 제한은 [box_carry_proposal.md](box_carry_proposal.md)에 기록한다.

HMI·투입 수량은 첫 결과가 나오기 전에도 이 값으로 세션을 안다(#68) |

| BoxTrack | `int32 track_id`, `float32 u`, `float32 v`, `int32[4] bbox` (x,y,w,h), `builtin_interfaces/Time stamp`, `geometry_msgs/Point position_base`, `bool position_valid`, `uint8 개폐 약 1.2 s 동안 손가락이 가림, measurements #4). **검출되지 않은 프레임에는 BoxTrack 을 발행하지 않는다** — `position_valid=false` 는 검출은 됐지만 좌표를 믿을 수 없을 때만 쓴다. **확정:** box_tracker 는 `min_hits`(기본 5, 약 0.17 s) 번 검출된 트랙부터 발행한다 — 손으로 올리는 순간의 1~2 프레임 트랙은 발행하지 않고, 그 번호는 재사용하지 않으므로 발행되는 ID 가 건너뛸 수 있다. **`bbox`·`u, v` 의 뜻:** 박스 **윗면** 의 축정렬 사각형과 윗면 중심(픽셀). seg 는 송장 사각형을 46×31 mm 비율로 넓혀 구하고 중심은 송장 중심이다(원근으로 보이는 옆면은 넣지 않는다). yolo 도 같은 정의로 학습한다(ADR-0004). **`yaw_base`·`yaw_valid`(Sprint 2 S2-T16, BRD v1.5 TR-SERVO-04 — 정의 확인: 박병후 10/13·김학민 10/14 #51 리뷰. 정확도는 아래 J6 측정 전):** `yaw_base` = 촬영 시각(`stamp`)에 관측한 **박스 긴 변(46 mm, 송장 긴 변과 같은 방향) 의 베이스 XY 평면 각도**, rad, 베이스 +X 에서 +Z 축 기준 반시계가 양. 파지 면이 180° 대칭이라 (−π/2, π/2] 로 접는다(+X 와 나란하면 0). box_tracker 가 송장 minAreaRect 의 긴 변 위 두 점(중심 ± 송장 긴 변 절반)을 **`position_base` 와 같은 출처·같은 변환**(핸드아이 = 촬영 시각 pose 의 광선-평면 교점, 호모그래피 = H)으로 베이스에 옮겨 atan2 로 구한다 — 카메라(J6) 회전은 pose 에 들어 있어 따로 보정하지 않는다. 벨트 방향과의 상대각·목표 각·데드밴드는 belt_servo 가 정한다(TR-SERVO-05). `yaw_valid=false` 면 `yaw_base` 를 쓰지 않는다(0): `position_valid=false` 이거나, 검출기가 각도를 주지 않거나(yolo 축정렬 bbox), 두 점 중 하나라도 변환이 무효일 때. **`yaw_valid=true` 의 수치 조건(seg, box_detect.SegParams 기본값):** 위 조건에 더해 BoxTrack 이 나가는 송장은 모두 면적 ≥ 6000 px²(원본 해상도 — 긴 변 약 98 px 이상, 관측 자세에서는 약 172 px)·긴/짧은 변 비 1.6 ± 0.3·회전 사각형 채움 ≥ 0.8 을 통과했고, 화면 가장자리(4 px)·벨트 영역 경계에 닿지 않았다 — 이 중 하나라도 어긋난 프레임은 BoxTrack 자체가 나가지 않는다. 베이스로 옮긴 긴 변 두 끝이 1 mm 보다 가까우면 BoxTrack 은 나가고 `yaw_valid=false`(`tracker_logic.yaw_from_ends`)다. 검출 바닥값은 J6 0~90° 합성 녹화에서 1.3°(tools/README.md). **소비 규칙(belt_servo, 박병후 10/13):** ±90° 경계에서 부호가 튀므로 한 프레임 값을 목표로 쓰지 않는다 — OBSERVE 동안 `yaw_valid=true` 프레임들의 각을 2θ 공간(cos 2θ, sin 2θ)에서 모은 중앙값의 절반을 목표 각으로 쓴다. 유효 프레임 수 조건·데드밴드(3~5°, 관측 데이터 뒤 확정)는 belt_servo 가 정한다(TR-SERVO-05). 정확도는 J6 0·15·30·45° 측정 전(S2-T16) — 그 전에는 관측 기록용(TR-SERVO-07 "yaw 관측만" 단계) |
