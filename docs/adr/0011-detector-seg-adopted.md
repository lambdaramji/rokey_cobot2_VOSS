# ADR-0011: 기본 박스 검출기는 OpenCV 분할(seg)로 확정, YOLO 는 대비책

- 날짜: 2026-10-08
- 상태: 승인됨 (2026-10-08, PL 남현지)
- 결정자: 남현지 (비전)
- 관련 SR / pending-decisions #: SR-SW-07, TR-PICK-02·03, T17(#26), pending #17. ADR-0004 를 잇는다(ADR-0004 "결과" 절: 10/08 비교 결과는 새 ADR 로)

## 배경
- ADR-0004 결정 3 은 "10/08 공용 PC 에서 분할과 YOLO 를 같은 녹화·정답셋으로 비교" 였다.
- 10/07 사람 확인 세트(박스 187, 손·빈 벨트 25)에서 둘은 같았다: 박스 187/187, 오검출 0/25(개인 PC). 다른 점은 화면 끝에 걸린 박스로, YOLO 는 잘린 박스도 잡아 중심이 치우친다(분할은 송장이 화면 끝에 닿으면 내지 않는다).
- 10/08 공용 PC 실시간(김학민 측정, measurements-1008 #1): 분할로 29.8~30.0 Hz, 검출 p95 4.0~4.2 ms, 루프 p95 4.3~4.6 ms, 카메라→발행 p95 49 ms. 기준(30 Hz, 검출 ≤ 20 ms, 지연 ≤ 100 ms)을 여유 있게 넘는다.
- box_tracker 노드는 분할만 연결돼 있다. YOLO 경로는 화면 끝 박스 거르기와 ONNX 런타임·GPU 설정이 더 필요하다.

## 결정
1. **G0·G1(게이트)·시연의 기본 검출기는 분할(`detector: seg`)** 이다. 게이트 측정 중에는 바꾸지 않는다(ADR-0004).
2. ADR-0004 결정 3 의 "공용 PC 에서 두 방식 비교" 는 하지 않는다. 분할이 이미 모든 기준을 넘었고, 같은 정답셋 성적이 같아 YOLO 로 얻을 것이 없다.
3. **YOLO v1(ONNX)은 대비책**으로 둔다. 조명이 바뀌거나 손·그림자 오검출이 시연장에서 생기면 그때 노드에 붙인다(화면 끝 박스 거르기 포함). 가중치는 레포 밖(`~/voss_ws/models/`, Drive)에 둔다.
4. T17 검출률 ≥ 99% 의 공용 PC 값은 실시간 벨트 흘리기 녹화(김학민, 10/08 이후)로 잰다. 그 전까지 검출률은 10/06 녹화 평가(ADR-0004 결과, 참고값)다.

## 고려한 대안
- YOLO 로 전환: 같은 성적에 GPU·ONNX 의존과 VRAM 몫(Whisper·PaddleOCR 와 8 GB 공유)이 늘고, 잘린 박스 처리가 더 필요하다. G0 이틀 전에 바꿀 이유가 없다.
- 둘 다 돌려 다수결: 지연·복잡도만 늘고 이득이 확인되지 않았다.

## 결과
- pending #17 결정(분할). `docs/architecture.md` 배포 표의 "box_tracker(YOLO)" 를 분할로 고친다.
- 비전 컨테이너(T22)는 box_tracker 에 GPU 가 필요 없다. GPU 는 label_reader(PaddleOCR)만 쓴다.
- 시연장 조명이 녹화 때와 다르면 `seg.*` HSV 임계를 다시 맞춘다(box_tracker.yaml, 노출 6 ms·WB 4600 고정 전제).
