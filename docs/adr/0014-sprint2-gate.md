# ADR-0014: Sprint 2 게이트 (10/13 18:00) — 팔레타이징·음성 기동을 시연에 넣을지

- 날짜: 2026-10-12 (판정 2026-10-13 18:00)
- 상태: 제안됨 — 판정 전
- 결정자: PL 남현지 (게이트 회의, 전원 참석)
- 관련 SR / pending-decisions #: BRD v1.4 10.2·10.8, TR-PAL-01~10, TR-VOICE-11~16, NFR-14~16, pending #19·#23. 절차·기록표 `docs/sprint2-gate.md`

## 배경
- Sprint 2(10/12~10/14)는 1~9장 MVP 위에 팔레타이징(10.4)과 음성 시스템 기동(10.6)을 더한다. 10/14 는 전체 리허설(단계 0~9) 3회, 10/15 시연이라 넣을지를 10/13 저녁에 정해야 리허설 대본이 고정된다.
- 두 기능은 여러 파트의 작업이 모두 붙어야 실기가 된다 — 팔레타이징은 S2-T01(인터페이스)·T02(팔레트 교시)·T03(PICK·DROP)·T05(sort_manager)·T07(sort_logger), 음성 기동은 S2-T09·T10. 하나라도 늦으면 기능 전체가 실기에 못 간다.
- 10/12 GitHub 계정 정지로 머지가 막혀, 공용 PC 는 브랜치·bundle 로 빌드할 수 있다(쓴 커밋 해시를 기록).

## 결정 (제안)
- **판정 기준:** 팔레타이징 = 3개 동 경로(대치 → 역삼 → 청담) 실기 1회 완주, 음성 기동 = 실기 1회 성공. 정의는 `docs/sprint2-gate.md` §1 — 측정 중 바꾸지 않는다.
- **미달 처리:** 그 기능은 시연에서 뺀다. 팔레타이징은 1개 동 경로 완주 기록이 있으면 단계 9 를 1개 동으로 줄인다. 1~8 단계는 그대로 시연한다(BRD 8.1).
- **게이트를 미루지 않는다.** 10/14 는 리허설에 쓴다.

## 고려한 대안
- A (제안): 10/13 18:00 에 한 번 판정, 미달 기능은 제외 또는 축소 — 리허설 대본이 10/13 밤에 고정된다. 늦게 붙은 기능은 시연에 못 들어간다.
- B: 10/14 오전까지 연장 — 리허설 3회 중 1회 이상이 미확정 대본으로 돌아가고, 1~9장 리허설 시간이 준다(BRD 10.2 우선순위 ①에 어긋남).
- C: 기준을 낮춤(예: 팔레타이징 1개 동만으로 통과) — 시연 단계 9 의 "배송 순서대로 싣는다"(10.8)를 보여 주지 못한다. 축소는 미달 처리로만 둔다.

## 결과
- 판정 뒤 `docs/plan.md` 10/13 줄, `docs/demo-script.md` §6(뺄 단계), pending #19(박스 구성)을 갱신한다.
- 단계 9 가 빠지면 sort_manager PALLETIZING 코드는 남기되 시연 중 palletize 를 보내지 않는다. 단계 0 이 빠지면 g0-runbook 수동 기동으로 시연을 시작한다.
