# ADR-0004: 박스 검출은 OpenCV 분할을 먼저, 그 결과로 YOLO 를 학습해 전환 판단

- 날짜: 2026-10-06
- 상태: 승인됨 (2026-10-06, 결정 담당 남현지)
- 결정자: 남현지 (pending-decisions #7 담당)
- 관련: T17(#26), pending #7, SR-SW-07(v0.1) / SYS-FR-003(v0.2), BRD TR-PICK-02·2.3, R-05

## 배경
- 조건: 박스 1종(46×31×27 mm, 윗면 흰 송장), 한 번에 1개, 배경은 고정된 벨트, 손목 카메라(하강 중 크기 변화), 개인 PC 에 GPU 없음, 2주.
- 요구: 30 Hz 검출(TR-PICK-02), 관측 지연 ≤ 100 ms(TR-PICK-03). T17 완료 기준 검출률 ≥ 99%(엑셀).
- BRD 2.3: 과제 필수 기술 "객체 탐지"는 기본안 YOLO, 세그멘테이션으로 대체 가능.
- 10/07 에 A 흐름(박스 1개 인식→파지→적재)을 잇기 시작해야 하는데, YOLO 는 촬영→라벨→학습→export→GPU 컨테이너까지 경로가 길다.

## 결정
1. **box_tracker 1차 구현 = OpenCV 색·형태 분할.** HSV 임계 + 형태 연산 + 외곽선 → 면적·종횡비(46:31 ≈ 1.5) 필터 → bbox·중심. 학습 없음, CPU 로 개인 PC 녹화 재생 개발 가능.
2. **분할 결과를 자동 라벨로 써서 YOLO nano 학습.** 10/06 촬영 영상 → 분할 박스를 YOLO txt 로 저장 → 썸네일 시트로 육안 검수, 틀린 프레임은 고치지 않고 버림 → Colab 학습 → ONNX export. 라벨링 도구 설치 없음(pending #7 "라벨링 도구" 결정).
   - **비교 정답셋은 따로 만든다.** 자동 라벨로 학습하면 YOLO 가 분할을 넘기 어렵고 평가가 쉬운 프레임에 몰리므로, 학습에 쓰지 않은 구간에서 사람이 직접 확인한 프레임 200장(서로 다른 박스 통과 10회 이상에서 고르게, 통과당 최대 20장)을 정답셋으로 둔다(손가락·그림자·화면 경계 프레임 포함).
3. **10/08 공용 PC 에서 두 방식을 같은 녹화 영상으로 비교**한다. 기준: 정답셋 200장에서 검출률 ≥ 99%(T17), 검출 ≤ 20 ms·루프 ≤ 100 ms(voss_vision/CLAUDE.md, TR-PICK-03), 그리퍼 손가락·그림자 오검출 0회. YOLO 가 모든 기준을 넘고 분할보다 나쁘지 않으면 YOLO 를 기본, 분할을 폴백으로 둔다. 결과 수치는 `docs/measurements-1008.md`(10/08 측정 기록, 새 파일)에 적고 10/08 결과 ADR 에서 참조한다.
4. 출력 계약 `/voss/vision/box`(BoxTrack)은 방식과 무관하게 동일. box_tracker 파라미터 `detector: seg | yolo` 로 고른다.
   - `detector` 와 HSV 임계값은 **voss_vision 패키지 파라미터 YAML** 에 둔다(voss_config 아님). 비전 컨테이너 launch 가 넘기고, box_tracker 는 기동 때 `detector` 값을 로그에 남긴다.
   - `stamp` 는 두 방식 모두 계산 시각이 아니라 원본 이미지 `header.stamp`(카메라 촬영 시각)를 그대로 쓴다 — belt_servo 지연 보정의 기준.
   - track_id 부여 규칙은 방식과 무관하게 `docs/interfaces/voss_msgs.md` BoxTrack 행을 따른다.

## 고려한 대안
- YOLO 만: 조명 변화에 강하고 과제 요구에 정확히 맞지만, 라벨링·학습·GPU 컨테이너가 끝나기 전까지 A 흐름을 못 잇는다. 개인 PC 에서는 CPU 추론이라 30 Hz 검증 불가.
- 분할만: 가장 빠르지만 조명 변화·그리퍼 손가락·그림자에 약하고, "객체 탐지" 과제 요구를 AI 모델로 보여 주기 어렵다.
- 깊이 기반 분할: 규칙 4(깊이 금지).

## 결과
- 10/07 부터 분할 기반 box_tracker 로 박병후(belt_servo)·sort_manager 연동 시작 가능.
- **게이트(10/08 1차·10/10) 측정 중에는 `detector` 를 바꾸지 않는다.** 분할(CPU)과 YOLO(GPU)는 지연이 달라 `timing.latency_offset_ms` 가 틀어진다. 전환할 때는 박병후에게 알리고 latency_offset_ms 를 다시 잰다. 게이트 로그(ADR-0002)에 사용한 detector 를 적는다.
- 10/06 촬영은 계속 필요(YOLO 학습·비교용, 녹화 재생 개발용). 녹화 영상과 `.pt`·`.onnx` 는 커밋하지 않는다(규칙 8) — `.gitignore` 의 `data/recordings/`·`data/images/`·`models/` 경로와 README 의 내려받기 안내로만 둔다.
- 위험: 시연장 조명이 촬영 때와 다르면 분할 임계가 틀어진다 → 노출·화이트밸런스 고정(김학민 T33)과 함께 HSV 임계를 파라미터로 둔다. 촬영 때 노출값은 measurements-1006 #9 기록을 기준으로 삼는다.
- 10/08 비교 결과는 이 ADR 을 대체하는 새 ADR 로 쓴다(템플릿 상태값에 "갱신"이 없음). `docs/architecture.md` 의 "box_tracker(YOLO)" 표기도 그때 맞춘다.

## 구현 메모 (2026-10-07, #76)
- **결정 1 의 분할 대상을 박스가 아니라 송장으로 바꿨다.** 10/06 B bag 에서 골판지 색이 손 피부색과 거의 같아 박스 색 분할은 손을 잡는다. 흰 송장(40 × 25 mm, 1.6:1)은 밝기(V≈250)·모양이 뚜렷해서, 벨트 열 안의 송장을 찾고 박스 윗면(46 × 31 mm)으로 넓혀 bbox 를 만든다. 중심 = 송장 중심. 화면 끝에 걸린 송장은 중심이 치우치므로 내지 않는다(`voss_vision/box_detect.py`, 파라미터 `config/box_tracker.yaml`). 송장 없는 박스는 시연에 없다(BRD 2.4).
- **트래커:** BoxTrack.track_id 규칙 + `min_hits`(5) 확정 — 손으로 올리는 순간 1~2 프레임 트랙을 내지 않는다(`voss_msgs.md` BoxTrack).
- **10/06 bag 결과(개인 PC CPU, 참고값):** 빈 벨트+손 1350 프레임 오검출 0, A·C 각 박스 10개 = 트랙 10개, 확정 트랙 구간 검출률 99.92%·100%, 프레임당 2~3 ms. 완료 수치(정답셋 검출률·공용 PC 지연)는 10/08.
- **결정 2 정답셋 분할:** 학습 = A bag 전체(통과 10회) + B bag 앞쪽(손 음성), 정답 = C bag 전체(통과 10회, 벨트 속도가 달라 일반화도 본다) + B bag 뒤쪽. 사람 확인 225장 = 통과 10회 × 20장(안쪽 18 + 화면 경계 2) + 음성 25장(`tools/vision/make_check_sheets.py`). 데이터는 Drive `datasets/t17_yolo_v1/`.
- **정답 판정 규칙(사람 확인, 10/07):** 상자 유무는 송장으로 정한다. 송장이 온전히 보이면 상자 있음(골판지가 화면 끝에 잘려도, 손으로 놓는 중이어도), 송장이 화면 끝에 닿거나 잘리면 상자 없음, 박스가 아닌 것(손·그림자)은 상자 없음. 손가락이 송장 일부를 가리면 상자가 있든 없든 맞음으로 본다(note "손 가림"). 송장이 화면 끝에서 4~10 px 인 장면은 사람 눈과 검출기 모두 경계선상이고 파지와 먼 진입 구간이라 평가에서 뺀다. 결과 y 215 · n 10(모두 이 경계 장면), 사람 확인본은 Drive `datasets/t17_yolo_v1/check.csv`.
- **닫힘 연산 경계 버그 수정(10/07):** 송장 글자 구멍을 메우는 닫힘(21 px)이 OpenCV 기본 테두리 처리 때문에 화면 밖을 흰색처럼 다뤄, 끝에서 약 10 px 안쪽 송장을 화면 끝에 붙여 버렸다(`border_px` 4 가 실제로는 약 10 px). 화면 밖을 0 으로 덧대고 닫도록 고쳤다. 10/06 bag: 빈 벨트+손 오검출 0 그대로, A·C 트랙 10개 그대로, 트랙이 양 끝에서 1~2 프레임 길어짐, C 에서 손으로 놓는 중인 박스의 1 프레임 트랙 1개(위 규칙상 박스가 맞음). v1 자동 라벨(학습·정답)은 수정 전 검출기로 만들었지만 차이는 화면 끝 4~10 px 장면뿐이고 그 장면은 평가에서 빠지므로 v1 학습을 그대로 쓴다.
- **YOLO v1 결과(10/07, Colab T4 학습 40 epoch·best 26, 참고값):** 사람 확인 세트 박스 187/187(100%), 손·빈 벨트 오검출 0/25 — 분할과 같다(187/187, 0/25). 다른 점은 화면 끝에 걸린 박스다: YOLO 는 박스 자체를 배워서 잘린 박스도 낸다(경계 프레임 16/16, 박스 있는 프레임의 남는 상자 15개, 모두 화면 위·아래 끝에 닿음, 가장 많이 잘린 것은 높이 74 px ≈ 정상의 1/3). 그대로 발행하면 중심이 크게 치우치므로 box_tracker 의 YOLO 경로는 "화면 끝에 닿고 벨트 방향 길이가 기대값보다 짧은 상자"를 버린다(값은 구현 때). 지연은 이 PC CPU 에서 onnxruntime 중앙 24 ms(분할 2~3 ms) — 판정은 10/08 공용 PC GPU. `best.pt` 선택에 holdout 을 썼고 사람 확인 세트가 그 일부라 약간 낙관적일 수 있다.
