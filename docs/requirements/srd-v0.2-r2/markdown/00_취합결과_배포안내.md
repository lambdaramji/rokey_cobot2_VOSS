## 완료한 작업

네 명의 회신을 대조해 **공통 내용 16개를 SRD에 반영**했다. 서로 다른 주장·전제 또는 아직 답이 없는 계약·실측·승인 증거 **34개를 6개 조합의 상호확인서로 정리**했다. 34개가 모두 직접 충돌인 것은 아니며, 충돌과 정보 부족을 구분했다.

기존 70개 SYS/VT, 18개 IC, 26개 TBD ID를 유지했다. 이전 v0.2 r1과 팀원 원본 회신은 보존했다. 저장소의 코드·계약·ADR는 변경하지 않았다.

반영한 공통 내용은 A/B/C 순서, 기본 매핑·장비 가정, 박스 1개 투입·벨트 수동 운전, RGB·알려진 높이 사용, manager/servo/gateway의 기본 책임, 최종 결과 1건·중복 방지, DB commit·조회, DB 기준 이력, 단일 설정 원본·쓰기 주체, 명령 접수와 완료 구분, 정상/예외/작업자 대기 분리와 성능 목표다. 세부 좌표·시각·재시도·저장 키·완료 시점까지 확정했다는 뜻은 아니다.

## 먼저 확인할 차이

1. **좌표 공급:** 현지님은 픽셀을 보내고 소비자가 mm로 변환하는 안, 병후님은 현지님 쪽에서 베이스 위치를 m로 공급받는 안이다. 고정 자세 호모그래피가 움직이는 손목 카메라 추종에 유효한지도 확인한다. MC-001·002·004·010.
2. **재시도·액션:** manager 재시도와 servo 국소 재시도 중 책임을 정하고 phase·reason·안전 높이 인계의 의미를 맞춘다. MC-005·006.
3. **정지·재개:** 취소 접수/0속도 발행과 실제 정지를 구분한다. 파지 후 정지했을 때 자동 이동을 계속할지, 사람이 제거할지 정책이 다르다. MC-014·015.
4. **완료 시점:** 현지님은 복귀 전에 결과를 발행하지만 학민님의 MoveToZone은 복귀 후 응답한다. 실제 적재·결과 발행·복귀·DB commit의 이벤트를 따로 연결한다. MC-016·030.
5. **명령·집계:** FAILED를 남은 수에서 차감할지, Stats 제공자·전체 분류/이력 질의·보류 표현·TTS 중복 억제 책임을 확인한다. MC-021~025.
6. **추종 게이트:** 기존 문서의 14/20 미달 시 자동 개루프 전환과 병후님의 ‘실측 성능이 상당히 부족하다는 팀 판단 후 대안 검토’ 방향을 맞춘다. MC-008.
