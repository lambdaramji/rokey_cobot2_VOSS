### MC-003 — track/box/session/attempt 유일성과 재투입
- **판정:** 합의 제안
- **최종 규약:**

| ID | 생성 주체 | 의미 | 유일 범위 |
|---|---|---|---|
| `track_id` | box_tracker | 화면에서 박스를 추적하는 번호. 0.5 s(15프레임) 미검출 시 만료 | 노드 실행 중만. **DB 키 아님** |
| `session_id` | sort_manager | `start` 시각 `YYYYMMDDTHHMMSS` | 전역 |
| `box_id` | sort_manager | **투입 회차**마다 1개 = `<session_id>-<3자리 순번>` | 전역, **DB 유일키** |
| `attempts` | belt_servo | 한 goal 안의 파지 시도 횟수 1~3(MC-005) | box_id 안 |

- "처리 시도" = **투입 회차**(새 box_id)입니다. 파지 재시도는 attempts로 셉니다.
- 재투입(PASSED 후 다시 올림)은 새 box_id입니다. 물리 박스 번호는 시험 대장에 사람이 기록합니다.
- 노드를 재기동하면 새 session_id가 생깁니다. 초 단위라 같은 분 재시작에도 충돌이 없고, 연도를 포함합니다.
- 같은 결과가 중복 수신되면 DB가 box_id로 무시하거나 upsert합니다(정의석, #52).
- **예시:** `20261010T143012-004`. 재시도 2회 후 성공 → SortResult 1건, attempts=3, DB 1행.
- **두 사람 확인:** 남현지 10/06 / 박병후 대기 · **추가 확인:** #52(DB 키), #54

### MC-004 — 촬영·pose·제어 시각과 시계 이력
- **판정:** 일부 합의 — 정의 합의 제안, 오차는 실측 대기
- **최종 규약:**
  - **시계:** 시간에 민감한 노드(카메라, 비전 컨테이너, 서보, gateway)는 모두 공용 PC 한 대의 **시스템 시계(ROS time = system)**를 씁니다. 다른 PC(개발·HMI)는 시간 판단에 쓰지 않습니다.
  - **카메라 stamp:** realsense `header.stamp`, 호스트 시계로 변환된 촬영 시각입니다(global time). 10/07에 드라이버 설정을 확인하고 기록합니다.
  - **pose stamp:** 학민님 안대로 **조회 응답 수신 시각**입니다. 실제 측정 시각이 아니라고 명시합니다. 불확실성은 왕복 시간의 절반 정도로 추정합니다(10/07 RTT 실측). 10 cm/s 이동 기준 20 ms 오차는 약 2 mm입니다(추정).
  - **보간:** 비전이 pose 이력 1 s를 보관하고 촬영 시각으로 선형 보간합니다. 다음 경우 position_valid=false입니다.
    - 촬영 시각 앞뒤 pose 간격이 50 ms를 넘을 때
    - 이력 범위 밖일 때
    - 미래 시각일 때
  - **age:** 소비자는 `now − stamp`로 age를 계산합니다. stale 기준값은 박병후 TBD-020으로 정합니다(제안: 100 ms).
- **검증:** capture→BoxTrack 발행, capture→서보 소비 지연 로그(10/08 공용 PC). 실기 미수행.
- **남은 미정:** RTT·지연 실측(남현지·박병후, 10/08), pose 원천(김학민, #51·#53)
- **두 사람 확인:** 남현지 10/06 / 박병후 대기 · **추가 확인:** #51, #53

### MC-005 — 재시도 담당과 액션/attempt 경계
- **판정:** 합의 제안 (병후님 안 수용)
- **최종 규약:**
  - 파지 재시도는 **belt_servo가 한 goal 안에서** 국소적으로 합니다. 카운터의 유일 소유자는 servo, 최대 3회(최초 + 재시도 2, TR-PICK-07)입니다.
  - sort_manager는 박스당 **goal 1개**만 보내고, 재시도 goal을 보내지 않습니다. 최종 result로 결과를 확정합니다.
  - result에 `int32 attempts`를 추가하자고 제안합니다(병후님 액션 정의에 포함).
- **시퀀스:**
  - 1회 실패 후 재시도 성공 → result `grasped=true, reason=OK, attempts=2` → 적재
  - 3회 실패 → `grasped=false, reason=GRASP_FAILED, attempts=3` → SortResult FAILED 1건
  - 시야 상실 → servo 판단으로 재시도하거나 종료(reason은 병후님 enum) → FAILED
  - 안전 오류 → `DEVICE_ERROR` → 재시도 없이 manager가 PAUSED(MC-014)
- **두 사람 확인:** 남현지 10/06 / 박병후 대기

### MC-006 — 픽업 phase·성공 인계·reason enum
- **판정:** 합의 제안 (병후님 값 수용, 대문자)
- **최종 규약:**
  - phase: `PREPARE / TRACK / DESCEND / GRASP / LIFT / VERIFY`
  - reason: 병후님 목록(`OK / GRASP_FAILED / STALE_INPUT / DEVICE_ERROR / …`) + 취소 시 `CANCELED`(제안)
  - `grasped=true`의 의미: **물체를 잡고 안전 높이까지 들어 올려 확인(VERIFY)을 마친 상태.** 그 자세에서 manager에게 인계합니다. 인계 높이는 병후님·학민님이 정합니다.
  - err_u, err_v는 px로 유지합니다.
  - goal 수행 중 새 goal → reject(BUSY). timeout은 병후님 값을 따릅니다.
- **manager 소비:** result만 판단에 씁니다. feedback은 로그와 HMI 표시용입니다.
- **두 사람 확인:** 남현지 10/06 / 박병후 대기 · **추가 확인:** #53(김학민 모션 완료)

### MC-009 — 단일 설정 snapshot·스키마·단위·유효값
- **판정:** 합의 제안
- **최종 규약:**
  - 원본은 `config/voss_config.yaml` 하나입니다. 런타임 writer는 sort_manager뿐입니다.
  - 정적 값은 **bringup launch가 YAML을 읽어 노드 파라미터로 전달**합니다. 각 노드는 기동 시 `version`과 파일 sha256을 로그에 남겨 snapshot을 확인합니다.
  - **단위:** YAML은 사람 단위이고 키에 접미사를 붙입니다(`_mm`, `_deg`, `_cmps`). ROS 메시지와 제어 내부는 SI입니다. 변환은 로드 시 합니다.
  - **벨트:** 학민님 안을 수용합니다.
    - `belt.direction_base: [x, y, z]`: 베이스 기준 단위벡터, 부호 포함(오른쪽 진행)
    - `belt.speed_cmps`
  - **null과 0:** null은 미측정입니다. 해당 값을 쓰는 노드는 READY가 아닙니다. 0은 의미 있는 값일 때만 허용합니다(예: angular=0).
  - 서보 전용 값(Kp, 높이, 오프셋, watchdog, age)은 `voss_servo` 파라미터 YAML(박병후 소유)에 둡니다. 공유 값만 voss_config에 둡니다: belt, observe_pose, 캘리브레이션 경로, latency_offset.
- **변경 제안:** voss_config 스키마에 `belt.direction_base` 추가, `direction_axis`는 폐기 제안입니다. `docs/interfaces/voss_config.md`를 먼저 수정하는 PR을 남현지가 10/07에 올립니다.
- **두 사람 확인:** 남현지 10/06 / 박병후 대기 · **추가 확인:** #51, #53

### MC-014 — cancel·watchdog·실제 정지 확인
- **판정:** 합의 제안 (병후님·학민님 안 수용)
- **최종 규약:** stop 명령을 받으면 manager가 다음 순서로 처리합니다.
  1. gateway `/voss/robot/stop` 호출(최우선, 타입은 학민님 NEW-R-04)
  2. 액션 cancel
  3. 상태를 PAUSED로 전환
- **보장:**
  - servo는 cancel을 받으면 servo_cmd 발행을 멈춥니다.
  - gateway는 **명령 만료 watchdog**으로 일정 시간 servo_cmd가 없으면 로봇을 세웁니다(시간 값은 학민님·병후님).
  - cancel 결과(`CANCELED`)는 **gateway가 정지를 확인한 뒤**에 반환합니다.
  - 확인이 안 되면 `STOP_UNCONFIRMED` → manager는 PAUSED를 유지하고 경고를 띄우며, 새 goal을 금지합니다.
  - **물체를 잡고 있는 동안 자동 개방은 금지**합니다.
  - gateway 프로세스가 종료됐을 때의 장비 동작은 학민님이 시험합니다.
- **남은 미정:** stop 타입, watchdog 시간, 최대 정지 지연·거리(김학민·박병후, 10/08)
