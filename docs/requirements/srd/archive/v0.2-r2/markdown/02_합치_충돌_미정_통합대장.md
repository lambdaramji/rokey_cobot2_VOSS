## 1. 판정 기준과 핵심 결론

공통으로 수용한 기능·기본 책임·측정 정책은 SRD 본문에 반영했다. 한 담당자의 구현 선택은 담당 설계로 수록하되 상대가 해야 할 계약 변경으로 확정하지 않았다. 회신에 `확정 제안`, `팀 승인`, `실측 완료`라고 적혀 있어도 다른 회신·승인 기록·실측 자료와 대조해 근거 수준을 구분했다. 상충하는 두 안 중 하나를 임의로 골라 확정하지 않았다.

- **16개 공통 내용(AC-ID)**을 등록했다. 이는 공통 내용의 반영이며 전체 계약·요구사항의 최종 승인/실기 통과를 의미하지 않는다.
- **34개 상호 확인 항목(MC-ID)**을 6개 조합으로 묶었다. 명시적 충돌, 전제 차이, 상세 공백, 실측/승인 증거 부족을 구분했다.
- 기존 **70개 SYS-ID·70개 VT-ID·18개 IC-ID·26개 TBD-ID**를 유지했다. 새 인터페이스/필드·담당 변경은 임시 제안 ID로 연결했다.
- **26개 TBD는 모두 부분 반영 또는 미정**이다. A 계약을 닫아도 B 상세까지 닫지 않으며, 실기 성능 통과는 이번 회신만으로 확인되지 않았다.

핵심 충돌: 위치 공급 책임/고정 호모그래피의 이동카메라 적용, retry manager↔servo, pose 응답시각↔측정시각, canceled 반환↔실제정지, 파지후 수동제거↔자동재개, placed/result/복귀/commit 이벤트, FAILED 를 남은수에 포함하는지, 전체 분류 명령/이력 라우팅, TTS 중복 책임, 기존 자동개루프 전환 게이트.

## 7. 증거 수준과 원본의 내부 불일치

- 남현지의 LabelCrop·ReadLabel·ZoneMap 승인 보고는 구체 브랜치가 있으나 현재 로컬 main 에는 없다. 다른 회신은 직접 확인 일시가 없다. `승인 보고/동기화 확인 전`으로 남겼다.
- 김학민 회신에는 BRD v1.2 참조가 있다. 제공받은 기준은 BRD v1.1이라 내용 차이를 확인할 수 없다. MC-034.
- 정의석 PC 사양은 프로젝트 지침의 실측 완료 기록을 인용했다. 측정 원본은 첨부되지 않았고 로컬 #5는 빈 칸이다. `담당자 보고/원본 증거 미확인`으로 수록했다. 사양이 틀렸다는 판정은 아니다. MC-028.
- 정의석 말미의 ‘본인 확인 필요’ 목록은 stack/DB/schema 가 아직 확정안이 아님을 보여준다. PostgreSQL·React/Spring Boot·wake/Whisper/TTS 모델은 후보로 유지했다.
- 남현지 start 허용상태가 요약(IDLE·PAUSED)과 상세 전이표(IDLE 만)에서 다르다. MC-023에 포함했다.
- 남현지 가상 좌표시험 최대 1.72mm/pytest6개는 담당 보고의 **모의 증거**다. 실측 오차 또는 이번 취합 작업에서 실행한 결과로 쓰지 않았다.
- 원본의 일정 10/06~10/15 는 담당자 제안/기존 계획이다. 이번 상호 확인 마감이나 실제완료로 바꾸지 않았다.
