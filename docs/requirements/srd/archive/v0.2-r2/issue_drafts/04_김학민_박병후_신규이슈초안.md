- **차이/현재 근거:** 김학민: gripper 실제 완료 후 서비스 응답, 동시에 한 동작만/busy 거부, Modbus는 별도 연결. 박병후: async close 요청 중에도 추종을 계속하고, stop/watchdog은 우선 처리.

- **남길 답변/증거:** 모션/그리퍼 소유 상태·허용 동시성 표·async 호출 시퀀스·timeout/중복 close/stop 시험.
- **연결 ID:** SYS-FR-009·010, IC-ROBOT-01·03, TBD-014·015·019
- **작성·확인 책임:** 김학민 gateway 실행 모델, 박병후 비차단 호출

### MC-014 — cancel·watchdog·실제 정지 확인

- **차이/현재 근거:** 남현지: cancel 후 servo가 0속도 발행 후 canceled 반환 제안. 김학민: stop 서비스·pose 변화 없음 확인, 감시시간 미정. 박병후: 단발 0속도 의존 금지, 실제 정지 확인 후 cancel 완료. pose만으로 actualstop 판단하지 않음. 불확실하면 STOP_UNCONFIRMED/PAUSED/새goal금지.
- **공동 결정할 질문:** 정지 요청 담당·우선순위·독립 watchdog·command expiry·실제 정지 확인 근거/연속 확인 조건을 정할 것. gateway 프로세스 종료 시 장비 동작도 시험하고 물체 보유 중 자동 개방 금지 여부를 결정.
- **남길 답변/증거:** 단계별 stop/cancel/노드 종료 시퀀스·/voss/robot/stop 최종 타입·정지 모드·timeout/최대 지연·거리·confirmed/unconfirmed 표시와 재개 조건.
- **연결 ID:** SYS-SF-001·002, IC-PICK-01·ROBOT-03, TBD-005·017·019·020; NEW-R-04
- **작성·확인 책임:** 김학민 실제 중단, 박병후 액션, 남현지 전체 PAUSED
- **같은 계약의 추가 확인 조합:** 남현지–박병후([이슈 초안](../issue_drafts/01_남현지_박병후_신규이슈초안.md)), 남현지–김학민([이슈 초안](../issue_drafts/02_남현지_김학민_신규이슈초안.md))

### MC-016 — 적재 완료·결과 발행·복귀·DB 순서

- **차이/현재 근거:** 남현지: 최종 그리퍼 개방 성공 직후, 복귀 전 SortResult 발행, DB commit 기다리지 않음. 사이클 detected→result. 김학민: MoveToZone 내부에서 개방+observe 복귀까지 하고 응답. 박병후: 실제placed/observe_ready/db_committed를 분리, 정상 사이클detect→placed. 정의석: commit/조회가 A 완료 조건.

- **작성·확인 책임:** 김학민 모션 이벤트, 남현지 result, 정의석 commit, 박병후 측정

### MC-ID별 공동 회신 형식

주 작성자가 아래 형식으로 댓글을 남기고 상대가 같은 MC-ID와 최종 답변에 확인 댓글을 남깁니다. 여러 항목을 한 댓글에 묶어도 MC-ID는 각각 유지합니다. Word/Markdown 양식을 채웠다면 이 이슈 댓글에 파일과 증거를 첨부해도 됩니다.

```text
MC-ID:
판정: 합의 / 일부 합의 / 불일치 유지 / 실측 대기 / 해당 없음(이유)
최종 규약: 이름·타입·필드·값·단위·좌표·시각·QoS·완료/오류 중 해당 사항
A 최소 연결 답변 / B 후속 답변 / C 채택 상태:
변경 제안: 기존 SYS/IC/VT/카드 ID, 변경 전→후, 필수 이유, 영향받는 파트/계약/시험
실제 데이터 예시·시퀀스:
검증: 모의/실기, 목표/설정/실측, 조건·횟수·증거 경로/commit/PR
남은 미정: 이유·담당·KST 예정일·영향 단계
두 사람 확인: 이름·확인 일시
추가로 확인할 조합/MC-ID:
```

요구사항·ID·인터페이스/검증 카드의 수정·추가·삭제는 반드시 해결할 문제에 한해 신중히 제안합니다. 기존 행과 ID는 지우거나 재사용하지 않고 수정/삭제 제안으로 표시합니다. ID 변경은 이전→새 ID 대응을, 추가 항목은 담당별 임시 ID를 남깁니다. 관련 담당자 확인·PL 검토 후 병후가 확정 SRD에 반영합니다.

## 회신·상태 관리

- [ ] 모든 해당 MC-ID에 공동 답변 또는 미정 이유·담당·예정일을 남겼다.
- [ ] 두 사람의 확인 이름·일시와 실제 데이터 예시/증거를 남겼다.
- [ ] A 최소와 B 후속, C 채택 상태를 나눴다.
- [ ] 다자 계약의 추가 확인과 후속 구현/실기 작업은 연결된 MC-ID·기존 작업 이슈에 기록했다.

이 조합의 회신을 받으면 병후가 체크를 갱신합니다. 해당 조합의 확인 작업을 종료해도 다자 계약의 전체 승인·실측·G0/G2 수락 상태는 상위 #6에 따로 남깁니다. 해결되지 않은 필수 계약은 담당/기한/후속 이슈를 명시해 계속 추적합니다. 정상 자동 사이클과 예외 처리를 나누고 작업자 대기는 별도 기록합니다.
