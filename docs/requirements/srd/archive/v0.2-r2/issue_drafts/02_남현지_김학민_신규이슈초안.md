## 일정·범위

| 일정(KST) | 마감·목표 |
| --- | --- |
| 상호확인 공동 회신 | **2026-10-06 18:30까지** |
| 첫 실기 실험·실측 | **2026-10-07까지** |
| G0 실제 1박스 전체 흐름 통과 | **2026-10-10까지** |

G0는 실제 박스 한 개의 인식→이동 중 픽업→올바른 기본 구역 적재→DB commit·조회→복귀/다음 관측 준비가 모두 확인돼야 통과합니다. 구체 장비 시간·검토 방식·확인자는 별도 협의합니다.

**단계:** A는 최초 전체 흐름 필수, B는 최종 시연 필수(음성·HMI·예외·이력·재시도·성능·컨테이너), C는 G0 이후 채택하는 선택 범위(규칙 변경·신규 구역 교시)입니다.

### MC-ID별 공동 회신 형식

주 작성자가 아래 형식으로 댓글을 남기고 상대가 같은 MC-ID와 최종 답변에 확인 댓글을 남깁니다. 여러 항목을 한 댓글에 묶어도 MC-ID는 각각 유지합니다. Word/Markdown 양식을 채웠다면 이 이슈 댓글에 파일과 증거를 첨부해도 됩니다.

```text
MC-ID:
판정: 합의 / 일부 합의 / 불일치 유지 / 실측 대기 / 해당 없음(이유)
최종 규약: 이름·타입·필드·값·단위·좌표·시각·QoS·완료/오류 중 해당 사항
A 최소 연결 답변 / B 후속 답변 / C 채택 상태:
변경 제안: 기존 SYS/IC/VT/카드 ID, 변경 전→후, 필수 이유, 영향받는 파트/계약/시험
실제 데이터 예시·시퀀스:
검증: 모의/실기, 목표/설정/실측, 조건·횟수·증거 경로/commit/PR
남은 미정: 이유·담당·KST 예정일·영향 단계
두 사람 확인: 이름·확인 일시
추가로 확인할 조합/MC-ID:
```

요구사항·ID·인터페이스/검증 카드의 수정·추가·삭제는 반드시 해결할 문제에 한해 신중히 제안합니다. 기존 행과 ID는 지우거나 재사용하지 않고 수정/삭제 제안으로 표시합니다. ID 변경은 이전→새 ID 대응을, 추가 항목은 담당별 임시 ID를 남깁니다. 관련 담당자 확인·PL 검토 후 병후가 확정 SRD에 반영합니다.

## 회신·상태 관리

- [ ] 모든 해당 MC-ID에 공동 답변 또는 미정 이유·담당·예정일을 남겼다.
- [ ] 두 사람의 확인 이름·일시와 실제 데이터 예시/증거를 남겼다.
