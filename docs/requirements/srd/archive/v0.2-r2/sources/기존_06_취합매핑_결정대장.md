# VOSS SRD v0.2 — 취합 매핑·결정 대장 (박병후용)

**목적:** 팀원 회신의 질문 ID → TBD 빈 항목 → SYS 요구사항·IC 계약·SRD 장을 연결해 반영한다. 02~04를 팀원에게 보내고 05는 본인 작성, 이 대장은 취합자가 관리한다. 회신 파일은 원본으로 보관하고 합의되지 않은 제안을 승인값으로 덮어쓰지 않는다.

원 대화에 접근할 수 없어도 위 결정자·날짜·내용으로 적용 정책을 확인할 수 있다. 추가 결정은 같은 방식으로 확정 문구·근거 문서/판/요구사항 ID 또는 보관 경로를 남긴다. 정확한 시각은 제공되지 않아 날짜만 기록했다.

추가 기술 결정은 해당 담당자가 근거와 대안을 제출하고 연결 상대·PL이 확인한다. 현재 목표 수치는 BRD 목표로 유지하며 변경 필요 시 영향·수락 기준을 함께 검토한다.

- [ ] A 핵심 계약과 G0 입력·출력·DB 저장·복귀·안전이 연결되어 있다.
- [ ] B 필수 요구사항의 빈 값·모호한 표현·근거 없는 수치를 닫거나 승인된 보류로 기록했다.
- [ ] 각 요구사항은 조건·결과·목표·검증·담당·근거를 가진다.
- [ ] 송수신 필드·단위·시각·주기·QoS·실패·cancel·완료 의미가 같다.
- [ ] 정상/예외 사이클, 작업자 대기, 재시도·재투입의 측정/집계 기준이 같다.

- [ ] SRD 승인 후 원본·저장소 사본·계약·메시지 정의의 버전을 맞췄다.

문서 정보 완성과 실제 구현·실기 수락은 별개다. 문서 기준선에는 승인 내용을, 시험 결과에는 실제 수행 여부를 기록한다. **승인된 보류는 해당 요구사항 충족/시험 통과를 뜻하지 않는다.** 보류가 있는 문서 발행 시 위 고정 필드를 기록하고, G0/G2 통과에 필요한 미정 기준을 통과로 처리하지 않는다. 필수 수락 기준의 면제·변경은 별도 변경 승인으로 처리한다.
