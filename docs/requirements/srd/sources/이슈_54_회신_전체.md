### MC-003 — box/session/attempt → #52 참조
- **판정:** 합의 (DB PK = `box_id`, `ON CONFLICT DO NOTHING`, `attempts` 컬럼)
- **병후 님 시험대장과의 대응:** 물리 박스 시험대장의 "투입 회차 1번"이 `box_id` 1개에 해당합니다. 같은 물리 박스를 재투입하면 새 box_id가 됩니다. 시험대장에 `box_id`를 적는 칸을 두면, DB의 `sort_log`와 1:1로 대조할 수 있습니다.
- **검증 (VC-EUS-DB-01):** 정상 10건 → 10행, 같은 box_id 5회 재발행 → 행 수 불변, 재기동 3회 → 행 유지.

### MC-016 — 적재·결과·DB 순서 → #52 참조
- **판정:** 합의
- **병후 님 분리안 수용:** `placed`, `result`, `observe_ready`, `db_committed`를 서로 다른 이벤트로 기록하는 데 동의합니다. 의석 측은 `db_committed`를 제공합니다.
  - `db_committed` = `sort_log.inserted_at` (PostgreSQL `now()`, 공용 PC 시계)
  - `placed` = `sort_log.finished_at` (SortResult.stamp = placed_stamp)
- G0 판정은 commit과 같은 box_id 조회가 모두 성공해야 합니다(4단계).

### MC-021 — 남은 수 → #52 참조
- **판정:** 합의 (PL 결정: 처리 완료 = PLACED + HELD + FAILED, PASSED 제외)
- **물리 분모 확인 요청:** 예정 수량은 **물리 박스 수**입니다. 시험에서 PASSED 후 재투입한 박스는 물리적으로는 1개이지만 box_id는 2개가 됩니다. 성공률 분모를 물리 박스 기준으로 셀지, box_id 기준으로 셀지 MC-031에서 함께 정해 주세요.

### MC-024 — 질문 30초 → #52 참조
- **판정:** 합의 (30초 = say 발행 시각부터)
- **측정 증거:** human_wait의 시작과 끝은 manager 로그에서 가져옵니다(say 발행 → 유효 답 또는 timeout). 의석 측은 speech_out 로그(`say_received`, `tts_start`, `tts_end`, monotonic + wall clock)와 intent_parser 로그(`utterance_end`, `intent_published`)를 제공합니다. 모두 공용 PC 한 대의 시계입니다.

### MC-027 — DB 장애 → #52 참조
- **판정:** 합의 (manager 비차단, sort_logger jsonl 스풀 + 재시도, DB_ERROR 표시)
- **G0 수락 조건:** G0 실행 중 `/voss/log/status`가 한 번이라도 `DB_ERROR`이면, 그 회차는 G0 증거로 쓰지 않습니다. 장애 시험은 G0와 분리해 VC-EUS-DB-01에서 따로 합니다.

### MC-030 — 정상 사이클 경계·재시도 분류
- **판정:** 일부 합의 — 의석 측은 **증거 제공자**입니다. 이벤트 정의는 박병후·남현지·김학민 님이 정합니다.
- **최종 규약(의석 측):**
  - DB 한 행에 사이클 계산용 시각이 2개 들어갑니다. `started_at` = SortResult.started_at(t_detect, 남현지 정의), `finished_at` = placed_stamp(김학민 MoveToZone 응답)입니다.
  - **정상 사이클 = 병후 님 안(t_detect → t_placed)을 수용**합니다. `db_committed`는 사이클에 넣지 않습니다.
  - 분류는 SQL로 고정하고, 사후에 손으로 고르지 않습니다.
```sql
-- 정상 자동 사이클: 재시도 없음, 사람 개입 없음
SELECT box_id, EXTRACT(EPOCH FROM finished_at - started_at) AS cycle_s
FROM sort_log
WHERE session_id = :sid AND result = 'PLACED'
  AND decided_by = 'OCR' AND attempts = 1 AND started_at IS NOT NULL;
-- 예외: attempts > 1 (재시도), decided_by IN ('RECHECK','OPERATOR'), result IN ('HELD','FAILED')
-- 작업자 대기 구간은 manager human_wait 로그로 따로 (MC-024)
```
- 재시도를 정상에서 빼고 예외로 분류하자는 병후 님 안에 동의합니다.
- **실제 데이터 예시 (CSV, Spring Boot `/api/export`로 내보냄):**
```
box_id,session_id,result,decided_by,attempts,started_at,finished_at,inserted_at,cycle_s
20261010T143012-004,20261010T143012,PLACED,OCR,1,2026-10-10T14:31:02.120+09:00,2026-10-10T14:31:24.870+09:00,2026-10-10T14:31:24.912+09:00,22.75
```
  (값은 형식 예시이며 실측이 아닙니다.)
- **남은 미정:** t_detect를 "최초 유효 촬영 시각"으로 할지 "검출 처리 시각"으로 할지(남현지), placed를 "개방 ack 시각"으로 할지(김학민). 의석 측은 받은 값을 그대로 저장합니다.

## 박병후 회신 — #54 박병후–정의석

작성 기준: 2026-10-06 KST. 병후 측 검토와 방향 결정을 정리합니다. 아래는 병후 측 확인·수정 요청이며, 공동 계약/PL 승인/구현/실측 완료를 뜻하지 않습니다. 다른 담당자 구현과 미확정 실측값은 구분해 두었습니다.

검토한 회신: [의석 #54 회신](https://github.com/lambdaramji/rokey_cobot2_VOSS/issues/54#issuecomment-6014656393) · [의석 #52 회신](https://github.com/lambdaramji/rokey_cobot2_VOSS/issues/52#issuecomment-6013764167).

### MC-003 — track/box/session/task/attempt 유일성과 재투입

**방향 확인, 유일성 상세 보완 요청.** box_id는 투입 회차마다 하나, 재투입은 새 box_id, 같은 goal 안의 파지 재시도는 attempts로 구분합니다. manager가 업무 ID를 만들고 servo는 내부 시도 횟수를 관리하며, 최종 결과와 DB 행은 box_id별 한 건으로 맞춥니다. 물리 박스 시험대장에는 session/box/goal/attempt 대응을 기록합니다.

초 단위 session_id만으로는 같은 초의 재시작 충돌을 막을 수 없습니다. 현지님·의석님이 생성/재시작 규약과 DB 문자열 길이·중복 처리 정책을 함께 맞춰 주세요. retry·reinsert·중복 수신은 서로 다른 사례로 검증하겠습니다.

### MC-016 — 적재 완료·결과 발행·복귀·DB 순서

**병후 담당은 픽업 인계와 측정 증거 확인입니다.** 적재/개방/복귀는 학민 gateway, 업무 결과 확정·SortResult는 현지 manager, 저장·commit·조회는 의석 logger/DB가 담당합니다. servo에 MoveToZone·최종 업무 결과·DB 처리를 추가하지 않습니다.

placed/result/observe_ready/db_committed/query를 동일 box에 연결하되 서로 다른 사건으로 기록해 주세요. placed_stamp의 개방busy 해제·폭 도달 확인 시각은 실제 적재의 proxy로 명시하고 올바른 적재와 영상으로 대조해야 합니다. MoveToZone 응답 수신 시각을 실제 관측 자세 도달 시각으로 단정하지 않습니다. 적재 후 복귀 실패/응답 유실에서 중복 처리하지 않도록 학민님·현지님이 상세를 맞춰 주세요. G0는 commit 성공과 같은 box 조회 증거도 필요합니다.

### MC-021 — 남은 수에서 FAILED 포함·재투입 집계

**현지님·의석님의 운영 집계 방향을 확인합니다.** 처리 완료=PLACED+HELD+FAILED, PASSED 제외 방향과 물리 박스 예정 수량을 취합하겠습니다. FAILED가 처리 건수에 포함돼도 파지/적재 성공으로 세지 않습니다.

업무 remaining·DB 행 수·투입 회차·물리 박스 성공률 분모를 구분합니다. 재투입의 새 box_id는 시험대장의 동일 물리 박스에 연결합니다. remaining 계산과 재투입에 따른 계획량 정합은 manager/DB 담당자가 확인해 주세요.

### MC-024 — 질문 ID·답변 유효성·30초·TTS 실패

**질문/음성 구현은 현지님·의석님 확인, 병후는 대기 구간을 측정합니다.** 30초 타이머는 manager의 say 발행부터 세는 담당자 방향을 확인합니다. human_wait는 say 발행→유효 답 또는 timeout으로 기록하고, say_received/tts_start/tts_end 및 utterance_end/intent_published와 구분해 주세요.

발화 시작의 box_id 연결은 확인하되 같은 박스의 pause/resume 뒤 재질문에는 이전 답이 섞일 수 있습니다. 질문 회차/수락 창·늦은 답·TTS 실패·타이머 재시작은 두 담당자가 정합해 주세요. servo에 별도 질문 서비스를 추가하지 않으며 B 상세 복구와 연결합니다.

### MC-027 — DB 장애·다음 박스 허용·durable 보존

**병후 시험 의견: 정상 G0와 DB 장애 복구 시험 분리에 찬성합니다.** 의석님 의견대로 DB_ERROR 없는 정상 회차와 오류 후 commit·조회가 회복된 장애 회차를 구분해 증거를 남기는 것이 좋겠습니다. 복구 성공과 이전 오류 기록을 모두 보존하고 물리 적재 결과를 덮어쓰지 않습니다.

MC-027은 servo 구현 범위가 아닙니다. manager 비차단 운전·spool/재전송·장애 표시는 현지님·의석님이 확인하고, 최종 G0 수락 조건·시험 구간은 관련 담당자/PL이 정합해 주세요. 이 시험 분리 의견으로 servo 정지 정책을 추가하지 않습니다. 프로세스 종료·디스크 full·spool 한도/경고·발행→logger 수신 유실에 대한 보장 범위도 확인 부탁드립니다.

### MC-030 — 정상 사이클의 감지/적재 경계·재시도 분류

**감지→실제 적재의 정상 cycle 및 재시도 예외 분류 방향 확인.** t_detect는 해당 박스의 첫 유효 BoxTrack 촬영 시각을 기준으로 정합하고 처리/수신 시각도 보존합니다. t_placed는 실제 적재 완료 근거와 대응시킵니다. 개방 확인 시각을 사용할 때는 proxy임을 명시하고 실제 적재와 대조해 주세요.

정상 자동 cycle은 attempts=1·decided_by=OCR·outcome=PLACED이며 재시도/재확인/작업자 개입은 예외로 따로 보고합니다. human_wait도 별도 구간입니다. 복귀·result·commit·조회는 각각 기록하고 DB commit은 정상 cycle에 포함하지 않습니다. 정상 cycle은 박스별≤30초 목표로 판정하고 평균·최대 및 원본을 함께 보고합니다. 사건 누락/무효 시각을 정상 표본으로 계산하거나 기록에서 삭제하지 않습니다.

### MC-031 — 시험 분모·판정·카드와 성능 측정 범위

**사전 고정 분모와 원본 증거 원칙 확인.** 1박스 G0, 20사례≥14 성능 점검, 최종10물리박스≥8 목표를 서로 다른 판정으로 유지합니다. 물리 박스·투입 회차·goal/attempt를 각각 기록하고 재투입/재시도로 분모를 임의 변경하지 않습니다. 실패·timeout·오류·재시험도 원본 기록에 남깁니다.

관측 지연≤100ms 목표에 대해 capture→비전 발행과 capture→servo 소비를 나누고 평균/p95/최대·초과 횟수/비율을 보고합니다. **100ms 초과 자체로 stop/cancel/PAUSED/STALE_INPUT을 발생시키지 않습니다.** 100ms 초과 관측을 일괄 폐기해 같은 중단을 유발하지도 않습니다. 입력 완전 상실·무효 좌표·명령 만료·장비 오류는 별도 정책으로 검증합니다. p95≤100ms 합격 기준 변경 제안은 검증카드/PL에서 확인하며, 위치≤5mm 등 제안값과 실측을 구분합니다.

### 상세 확인과 검증 연결

DB 시각 한 가지는 정정이 필요합니다. PostgreSQL now()/inserted_at은 트랜잭션 시작 시각이며 실제 commit 완료 시각이 아닙니다. inserted_at의 의미는 유지하되 commit 성공 확인 로그/ack와 같은 box_id의 별도 조회 결과를 증거로 연결해 주세요.
