### MC-020 — SortResult → DB 필드·enum·누락 데이터
- **판정:** 합의 제안 — 메시지 확장 필요
- **enum(대문자):**

| 필드 | 값 | 의석님 안과의 대응 |
|---|---|---|
| outcome → DB `result` | `PLACED / HELD / FAILED / PASSED` | PASSED 추가(비대상 통과, 집계 제외) |
| decided_by | `OCR / RECHECK / OPERATOR / NONE` | AUTO는 OCR 또는 RECHECK로 세분. **TIMEOUT은 판정 주체가 아니라 reason** |
| zone | `A / B / C / RECHECK / HOLD / ""` | HOLD 수용 |
| reason | `"" / LOW_CONF / NO_ANSWER / NON_TARGET / STOPPED / DEVICE_ERROR` + 병후님 픽업 reason(`GRASP_FAILED` 등) | — |

- **SortResult에 끝에 추가할 필드(NEW-V-02 확장):**

| 필드 | 의미 | DB 컬럼 |
|---|---|---|
| `string session_id` | 세션 | session_id |
| `int32 track_id` | 참고용 | track_id |
| `builtin_interfaces/Time started_at` | t_detect(첫 검출 촬영 시각) | started_at |
| (기존 `stamp`) | 결과 확정 = placed_stamp 또는 판정 시각 | finished_at |
| `string raw_text` | OCR 원문 | raw_text |
| `string dong_alt` | 2위 후보 | second_region |
| `string rule_version` | 적용한 zone_map version | rule_version |
| `string reason` | 위 enum | reason |
| `int32 attempts` | 총 시도 수 | retries = attempts − 1 (DB 계산) |

### MC-021 — 남은 수와 FAILED·재투입 집계 (PL 결정)
- **판정:** 남현지 안 — 의석님 확인 필요
- **최종 규약(BRD 8.1 근거: "재시도 후에도 실패하면 미분류로 집계"):**
  - **예정 수량 = 물리 박스 수**입니다(기본 10, HMI에서 변경 가능).
  - **처리 완료 = PLACED + HELD + FAILED**입니다. FAILED는 미분류로 처리가 끝난 것으로 보고, 시연에서 다시 투입하지 않습니다.
  - **PASSED(비대상 통과)는 처리 수에서 제외**하고 다시 투입합니다. 재투입하면 새 box_id입니다.
  - **남은 수 = max(예정 − (PLACED + HELD + FAILED), 0)**, 범위는 현재 session입니다.
- **집계 예:**

| 상황 | 예정 | PLACED | HELD | FAILED | PASSED | 남은 수 |
|---|---|---|---|---|---|---|
| 시작 | 10 | 0 | 0 | 0 | 0 | 10 |
| 대치동 우선: 박스1 PLACED, 박스2·3 PASSED | 10 | 1 | 0 | 0 | 2 | 9 |
| 박스2·3 재투입 후 PLACED | 10 | 3 | 0 | 0 | 2 | 7 |
| 박스5 파지 3회 실패 | 10 | 3 | 0 | 1 | 2 | 6 |
| 흐린 송장 무응답 | 10 | 3 | 1 | 1 | 2 | 5 |

### MC-023 — 전체 분류·이력 질의·HOLD·명령 인자
- **판정:** 합의 제안 (의석님 안 수용) + 남현지 회신 내부 불일치 정정
- **`/voss/sort/command`(Command: command, arg) canonical:**

| command | arg | 허용 상태 | 의미 |
|---|---|---|---|
| `start` | `""` 또는 `ALL` | IDLE → RUNNING. RUNNING 중이면 전체 분류로 모드 전환 | 운전 시작(기본 전체) |
| `priority` | 동 이름(필수, zone_map 허용 목록) | RUNNING·PICKING·RECHECK·ASKING, IDLE(저장만) | 다음 박스부터 그 동만 |
| `stop` | `""` | 모든 상태 → PAUSED | 소프트웨어 정지 |
| `resume` | `""` | **PAUSED에서만** | 재개 |
| `answer` | `<box_id>\|<동 이름 또는 HOLD>` | ASKING에서만 | 예외 질문 답 |
| `reset_zone` | 구역 | PAUSED | 용량 초과 후 비움 확인(#51 MC-018) |

- **정정:** 제 회신의 "start는 IDLE·PAUSED에서 유효"는 틀렸습니다. **start는 IDLE, 재개는 resume(PAUSED)만**입니다.
- `query_history`는 manager로 보내지 않습니다. intent_parser·hmi_bridge가 `/voss/log/query`로 직접 보냅니다(MC-022).
- "보류"는 intent_parser가 `HOLD`로 바꿉니다. zone 값은 모두 대문자입니다.
- 서비스 응답은 **접수 의미**이고, 완료는 SortState·SortResult로 확인합니다. command_id·TTL은 hmi_bridge가 처리합니다(MC-026).

### MC-024 — 질문 ID·답변 유효성·30초·TTS 실패
- **판정:** 합의 제안
- **최종 규약:**
  - **질문 ID = box_id**입니다. 질문 중에는 `SortState.state=ASKING`, `box_id`, `pending_question="역삼동|청담동"`이 표시됩니다.
  - **답에는 box_id를 함께 보냅니다**(`answer`, `<box_id>|<동 또는 HOLD>`). intent_parser가 최신 SortState에서 box_id를 채웁니다.
  - box_id가 다르거나 ASKING이 아니면 `ok=false`, "지금은 답할 질문이 없습니다"입니다. 이렇게 늦은 답이 다음 질문에 잘못 적용되는 것을 막습니다.
  - 유효한 답은 후보 2개의 동 이름 또는 HOLD입니다. 무효한 답이면 1회 재안내하고, 타이머는 유지합니다.
  - **30초 타이머**는 manager가 질문 문장을 `/voss/voice/say`로 **발행한 시각**부터 셉니다. TTS 재생 시작이나 완료 기준이 아닙니다.
  - TTS가 실패해도 HMI에 질문이 표시되므로 타이머는 그대로 갑니다(G0·B).
  - stop하면 타이머가 멈추고, resume하면 재발화와 함께 30초가 새로 시작됩니다.
  - **작업자 대기(human_wait)** = say 발행 → 유효 답 수신 또는 timeout입니다. manager 로그에 기록합니다.

```sql
CREATE TABLE sort_log (
  box_id        varchar(32)  PRIMARY KEY,            -- 20261010T143012-004
  session_id    varchar(16)  NOT NULL,
  track_id      integer,                             -- 참고용
```
