## 3. MC 별 최종 합의·남은 상세

### MC-001 — 픽셀→베이스 위치의 제공 책임·출력 단위

- 합의: 비전이 BoxTrack.position_base 에 촬영 시각의 박스 윗면 중심을 base_link·m로 제공한다. position_valid/source/calib_version을 함께 보내며, TCP 목표·지연/벨트 예측·파지 오프셋은 servo 단독 계산이다. 픽셀 필드는 유지한다.
- 남은 내용: 이동 변환·유효 범위의 실측은 MC-002에서 계속한다. 비전 변환을 servo에서 import/중복 구현하지 않는다.
- SRD 반영: §3.4·5.4 · 관련 ID: SYS-FR-007, IC-VISION-02, TBD-002·003; NEW-B-01
- 후속 담당·시점: 남현지·박병후 / 10/07~08 (계획·목표, 실제 수행 별도)
- 최종 확인 근거: [#50 최종](https://github.com/lambdaramji/rokey_cobot2_VOSS/issues/50#issuecomment-6028992757)

### MC-002 — 고정 관측 자세 호모그래피와 이동 카메라 추종

- 합의: 관측 자세 정지에서만 고정 호모그래피를 사용한다. 이동 카메라에서는 촬영 시각의 TCP pose 이력과 T_tcp→camera, 박스 윗면 평면을 사용한 위치 갱신이 G0 A 필수다. 동적 검증 전/시각 정합 불가 시 position_valid=false 다.
- 남은 내용: 핸드아이 결과·촬영 pose 정합·상류 외삽 범위·정적/동적 오차 실측 필요. 1.72 mm는 가상 시험값이고 ≤5 mm는 제안이다. #25·#41·#36, PR #48.
- SRD 반영: §3.4·5.4·10 · 관련 ID: SYS-FR-007·008, SYS-CT-002, TBD-002·014·020
- 후속 담당·시점: 남현지·김학민·박병후 / 촬영 10/07·동적 10/08 (계획·목표, 실제 수행 별도)

### MC-003 — track/box/session/task/attempt 유일성과 재투입

- 합의: track_id는 tracker 실행 중 증가하고 재사용하지 않으며 DB 키가 아니다. manager가 투입 회차마다 <session_id>-<3 자리 순번> box_id를 발급한다. session_id=YYYYMMDDTHHMMSS-xxxx(랜덤 4hex), manager 재기동은 새 세션. 파지 retry는 같은 box_id/goal의 attempts, 재투입은 새 box_id 다. DB PK=box_id, 중복은 DO NOTHING이다.
- 남은 내용: 4 자리 난수는 충돌 가능성을 줄이며 절대 유일성을 보장하지 않는다. 충돌·순번 범위·정지/재개 시 세션 유지 확인 필요. DB session_id varchar(24), box_id varchar(32). #29·#21.
- SRD 반영: §3.4·5.8·7.1 · 관련 ID: SYS-FR-004·014, SYS-DT-001, TBD-003·007·008·012·022
- 후속 담당·시점: 남현지·정의석 / G0 전·DB10/09 (계획·목표, 실제 수행 별도)

- 합의: 민감 노드는 공용 PC 시스템 시계를 사용한다. 카메라 촬영 stamp를 crop/OCR 까지 보존한다. robot pose stamp는 get_current_posx 응답 수신 시각이며 실제 측정 시각이 아니다. gateway가 요청·응답·RTT·큐 대기를 로그로 남긴다. 응답 시각·RTT/2를 측정 시각·보장 오차로 쓰지 않는다.

- SRD 반영: §3.4·5.4·6.2 · 관련 ID: SYS-PF-007, IC-VISION-01·02, IC-ROBOT-02, TBD-003·014·020·026

### MC-005 — 재시도 담당과 액션/attempt 경계

- 합의: 파지 재시도는 belt_servo가 goal 하나 안에서 최초 포함 최대 3 회 수행한다. attempts의 유일 소유자는 servo 다. manager는 투입 박스당 goal 하나를 보내고 retry goal을 중복 생성하지 않는다. 장비·안전 오류는 자동 재시도하지 않는다.
- 남은 내용: 세부 timeout·재시도 가능 위치/시간·goal 실패 로그를 #36·#29에서 검증한다. 최대 3 회는 B 기능이며 A 연결에 모든 retry 시나리오 통과를 요구하지 않는다.
- SRD 반영: §3.3·5.5·SYS-FR-011 · 관련 ID: SYS-FR-011, IC-PICK-01, TBD-019; NEW-B-04
- 후속 담당·시점: 박병후·남현지 / G2 전 (계획·목표, 실제 수행 별도)
- 최종 확인 근거: [#50 최종](https://github.com/lambdaramji/rokey_cobot2_VOSS/issues/50#issuecomment-6028992757)

### MC-006 — 픽업 phase·성공 인계·reason enum

- 합의: phase=PREPARE/TRACK/DESCEND/GRASP/LIFT/VERIFY. result.grasped=true는 물체 확보 후 안전 높이 LIFT·VERIFY를 마친 인계다. reason=OK/GRASP_FAILED/LOST/OUT_OF_REACH/STALE_INPUT/DEVICE_ERROR/CANCELED와 action status를 매핑하며 manager는 reason으로 분기한다. BUSY/미준비 goal은 reject(result 없음). err_u/v는 px 다.
- 남은 내용: 인계 높이·자세·timeout은 실측/설정 검증 필요. 파지 방향은 31 mm 폭 파지로 PL 결정(pending #16, #70), −19mm는 PL 결정값이다. 39mm/14N/보고 폭은 T34 10회 시험으로 확인한다. #43·#36.
- SRD 반영: §5.5·10 · 관련 ID: SYS-FR-009·010, SYS-IF-002, IC-PICK-01, TBD-019; NEW-B-04
- 후속 담당·시점: 박병후·김학민·남현지(PL) / T34 10/07~08 (계획·목표, 실제 수행 별도)
- 최종 확인 근거: [#50 최종](https://github.com/lambdaramji/rokey_cobot2_VOSS/issues/50#issuecomment-6028992757) · [#53 최종](https://github.com/lambdaramji/rokey_cobot2_VOSS/issues/53#issuecomment-6028997780)
